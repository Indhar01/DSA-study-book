What is DSA and Why Should You Care?

Before we write a single line of code, let us talk about why you are here — and why learning DSA will be one of the most valuable investments you ever make as a software engineer.

📖 Story

Priya and Arjun both just got the same task: find one customer record in a file with one million entries. Priya starts at the top and reads line by line. Arjun pauses, scribbles something, and finishes in a blink. Priya is still reading. Arjun is already answering the interviewer's follow-up question.

Priya's approach: record 1 → check ✗ record 2 → check ✗ record 3 → check ✗ ... record 500,000 → found ✓ ← 500,000 steps Arjun's approach (sorted + binary search): check middle record 500,000 → too low, go right check record 750,000 → too high, go left check record 625,000 → too high, go left check record 562,500 → found ✓ ← 20 steps 1,000,000 records. Priya: ~500,000 steps. Arjun: ~20 steps.

The difference is not talent. It is knowing the right data structure and algorithm for the job.

The Story of Two Engineers

Imagine two engineers are both tasked with finding a specific customer record from a list of one million users. The first engineer writes a straightforward solution: she loops through every single record, one by one, checking if it matches. On her laptop, it finishes in about 8 seconds. The second engineer thinks for a moment, organises the data differently, and writes a solution that finishes in under a millisecond — thousands of times faster. They wrote roughly the same number of lines of code. The difference? The second engineer understood data structures and algorithms.

This is not a made-up story. This gap in performance — and in thinking — separates junior engineers from senior engineers, and it separates candidates who clear technical interviews from those who do not.

So, What Exactly Is DSA?

Let us define our terms clearly, because in this book we will never use a word without explaining it first.

A data structure is a way of organising and storing data in memory so that it can be accessed and modified efficiently. Think of it like choosing the right container in your kitchen. You would not store soup in a paper bag, and you would not carry loose grapes in a pitcher. Different containers work best for different purposes. In computing, an array is like a neat row of labelled boxes, a stack is like a pile of plates, and a queue is like the line at a coffee shop.

An algorithm is a precise, step-by-step set of instructions to solve a problem. It is a recipe. A good recipe not only produces the right dish — it does so efficiently, without wasting ingredients or time. Similarly, a good algorithm not only produces the right answer — it does so without wasting memory or computation.

🟣 Analogy

Think of your computer's memory as a city, and data structures as the different kinds of buildings in that city — apartments (arrays), warehouses (heaps), subway maps (graphs). Algorithms are the traffic rules and navigation strategies that let you move through that city efficiently. DSA is the art of being a brilliant city planner and a savvy navigator at the same time.

Why Do Product-Based Companies Test DSA?

You might be wondering: "I just want to build web apps. Why do I need to know about trees and graphs?" That is a completely fair question, and it deserves a direct answer.

Product-based companies — Google, Amazon, Meta, Microsoft, and hundreds of startups — use DSA interviews for three reasons:

  1. It reveals how you think. Solving an unfamiliar algorithmic problem under pressure shows your ability to decompose complexity, reason systematically, and communicate clearly — skills that matter every day on the job.
  2. It predicts performance on real problems. The engineer who can optimise a graph traversal will also spot the performance bottleneck in a production service. The thinking is the same.
  3. It is a shared language. When an interviewer says "this is an O(n log n) problem," everyone in the room understands exactly what that means. DSA is the universal vocabulary of software engineering.

Why Is DSA Especially Important for AI Engineers?

If you are pursuing an AI Engineer role specifically, DSA matters for all the above reasons plus a few more:

  • Data pipelines are just algorithms on data structures. Preprocessing millions of training examples, building feature stores, deduplicating datasets — these are all algorithmic problems.
  • Embedding lookups use hashing and trees. Vector databases and nearest-neighbour search rely directly on tree structures and graph algorithms.
  • You will debug ML systems. When your model training is slow or your inference service times out, understanding algorithmic complexity is what lets you diagnose and fix it.

Big-O Notation — Measuring the Cost of Your Code

How do you know if your code is fast enough? How do you compare two solutions without running them? Big-O notation is the ruler that every engineer uses to measure algorithmic efficiency — and once you understand it, you will see it everywhere.

📖 Story

Riya works at a library. Her boss asks: "How long does it take to find a book?" Riya answers honestly: "It depends." On a quiet morning, 2 minutes. During exam season with 10,000 requests — hours. Her boss wants a formula that works regardless of the day. That formula is Big-O.

Shelf with N books: Linear scan (no order): ████████████████████ O(n) Sorted + binary search: ██████ O(log n) Direct index lookup: █ O(1) N = 10: linear=10 ops, binary=4 ops, index=1 op N = 1000: linear=1000 ops, binary=10 ops, index=1 op N = 1000000: linear=1M ops, binary=20 ops, index=1 op As N grows → the gap between strategies grows MUCH faster.

Big-O gives Riya the formula her boss wanted: a rate that scales with input size, not with the clock on the wall.

The Problem with Measuring Time Directly

Suppose you write a function and it takes 0.3 seconds to run. Is that fast? It depends. Fast compared to what? On whose computer? With how much data? If you run the same code on a newer laptop with half the data, it might take 0.05 seconds. On an old server with ten times the data, it might take 30 seconds. Raw time measurements are unreliable because they depend on hardware, operating system load, and input size.

What we really want to know is: as the input grows larger, how does the runtime grow? That question is what Big-O notation answers.

🟣 Analogy

Imagine you are estimating how long it takes to read a book. Instead of saying "it takes 4 hours," you say "it takes roughly 2 minutes per page." That rate — 2 minutes per page — is your "complexity." A 100-page book takes 200 minutes. A 500-page book takes 1,000 minutes. The formula scales with the input. Big-O is exactly this: we describe how an algorithm's cost scales with the size of its input.

Formal Definition (Plain English Version)

Big-O notation, written as O(f(n)), describes the upper bound of an algorithm's growth rate in terms of input size n. In other words: in the worst case, as n gets very large, how does the number of operations grow?

We drop constants and lower-order terms because, at large scales, they do not matter. For example, if an algorithm does 3n + 5 operations, we say it is O(n). The 3 and the 5 are insignificant when n is a million.

The Most Common Complexity Classes

Let us walk through each complexity class from fastest to slowest, with an analogy and an example for each.

O(1) — Constant Time

No matter how large the input, the operation always takes the same amount of time. Accessing an element in an array by its index is O(1) — you jump directly to it, like knowing the exact page number in a book.

Python 
def get_first_element(arr: list) -> int:
    # No matter how long arr is, this is ONE operation.
    return arr[0]

O(log n) — Logarithmic Time

The number of operations grows logarithmically — meaning each step cuts the remaining work roughly in half. Binary search is the classic example. If you have 1,000,000 items, you only need about 20 steps to find anything. Think of it as looking up a word in a physical dictionary: you open to the middle, decide left or right, open to the middle of that half, and repeat.

O(n) — Linear Time

The operations grow proportionally with the input. If you have twice as much data, it takes twice as long. A simple loop through a list is O(n). Like reading every page of a book — more pages means proportionally more reading.

Python 
def find_max(arr: list[int]) -> int:
    # We visit every element exactly once: O(n)
    max_val = arr[0]
    for num in arr:
        if num > max_val:
            max_val = num
    return max_val

O(n log n) — Linearithmic Time

A loop that also does logarithmic work inside, or algorithms that divide and then recombine. Merge sort and heap sort run in O(n log n). This is the practical lower bound for comparison-based sorting — you cannot sort an arbitrary list faster than this.

O(n²) — Quadratic Time

A nested loop where both loops go up to n. Comparing every element to every other element is O(n²). With 1,000 elements, that is 1,000,000 operations. With 10,000 elements, it is 100,000,000. Quadratic algorithms become painfully slow at moderate scales.

Python 
def has_duplicate_slow(arr: list[int]) -> bool:
    # Outer loop runs n times, inner loop runs n times → O(n²)
    for i in range(len(arr)):
        for j in range(i + 1, len(arr)):
            if arr[i] == arr[j]:
                return True
    return False

O(2ⁿ) — Exponential Time

The work doubles with every additional element. Generating all subsets of a set is O(2ⁿ). With 20 items, that is over 1,000,000 operations. Exponential algorithms are almost always impractical without optimisation (such as dynamic programming).

O(n!) — Factorial Time

Generating every possible ordering (permutation) of n items. With just 12 items, that is 479,001,600 orderings. Factorial algorithms are only feasible for very small inputs.

Space Complexity

Big-O does not only measure time — it also measures memory usage. Space complexity is how much extra memory your algorithm needs as the input grows. A function that creates a copy of the input array uses O(n) space. A function that only uses a few variables regardless of input size uses O(1) space.

In many real-world scenarios — especially in AI engineering where datasets can be enormous — space efficiency matters as much as time efficiency.

Best, Worst, and Average Case

When we say an algorithm is O(n), we typically mean the worst case. But it helps to understand all three:

  • Best case: The most favourable input. Searching a list where the target is the first element is O(1) for linear search in the best case.
  • Worst case: The most unfavourable input. The target is the last element, or not present at all. This is what Big-O typically refers to.
  • Average case: Averaged over all possible inputs. For linear search, on average we look at half the list, so the average case is O(n/2) = O(n).
🔴 Common Beginner Mistake

Many beginners confuse "O(n)" with "slow" and "O(1)" with "fast." But remember: O(1) with a huge constant can be slower than O(n) for small inputs. Big-O describes how the algorithm scales, not its absolute speed. Always consider the actual input sizes you expect in practice.

🟢 Tip

When analysing a piece of code, count the loops. One loop → O(n). Two nested loops → O(n²). A loop that halves the input each iteration → O(log n). A loop inside a loop inside a loop → O(n³). This rough counting gets you 90% of the way there in interviews.

Chapter Summary

  • Big-O notation describes how an algorithm's cost scales with input size n.
  • We focus on the dominant term and drop constants.
  • Common complexities from best to worst: O(1), O(log n), O(n), O(n log n), O(n²), O(2ⁿ), O(n!).
  • Space complexity measures memory usage, not just time.
  • Big-O typically refers to the worst-case behaviour.

Arrays and Strings

Arrays are the foundation of almost everything else in computer science. If you can master the patterns of array manipulation, you will find that a surprising number of seemingly different problems all reduce to the same few ideas.

📖 Story

Sam is organising a row of 8 numbered lockers at a gym. Each locker has a fixed address. If he wants locker 5, he walks directly to position 5 — no searching. But if he needs to insert a new locker between positions 3 and 4, every locker from 4 onwards has to shift right. That is an array in a nutshell: instant access, painful insertion.

Locker Row (Array): Index: [ 0 ][ 1 ][ 2 ][ 3 ][ 4 ][ 5 ][ 6 ][ 7 ] Value: [ 12][ 7 ][ 3 ][ 19][ 5 ][ 8 ][ 14][ 2 ] ↑ O(1) access by index Insert 99 at index 2: Before: [ 12][ 7 ][ 3 ][ 19][ 5 ][ 8 ][ 14][ 2 ] Shift: [ 12][ 7 ][ ][ 3 ][ 19][ 5 ][ 8 ][ 14] ← 6 shifts After: [ 12][ 7 ][ 99][ 3 ][ 19][ 5 ][ 8 ][ 14] Cost: O(1) read, O(n) insert/delete at arbitrary position.

Every array problem in an interview is really a question about which operations you can afford.

What Is an Array?

Imagine a row of numbered mailboxes in an apartment building. Each mailbox has a fixed address (index), and you can instantly retrieve or deposit mail in any box by knowing its number. That is an array. In Python, this corresponds to a list — a contiguous sequence of elements, each accessible by a zero-based integer index.

Key properties of arrays:

  • Random access in O(1): You can jump to any element instantly using its index.
  • Fixed or dynamic size: In languages like C, arrays have a fixed size. Python lists are dynamic — they grow automatically as you append items.
  • Contiguous memory: All elements are stored next to each other in memory, which makes sequential access extremely fast due to CPU cache effects.

Strings Are Just Arrays of Characters

In Python, a string like "hello" behaves like an array of characters: ['h','e','l','l','o']. Many string problems are solved with exactly the same techniques as array problems. One key difference: Python strings are immutable — you cannot change a character in place. You must create a new string or work with a list of characters and join at the end.

The Two-Pointer Technique

Here is a pattern that will unlock dozens of problems. Instead of using one index to traverse an array, you use two indices simultaneously — one starting from the left and one from the right, both moving toward the middle (or both moving from the left at different speeds).

🟣 Analogy

Think of two people folding a long piece of fabric. One person holds the left end and walks right. The other holds the right end and walks left. They keep meeting and folding until they reach the middle. Together they process the entire fabric much more cleverly than one person walking the whole length alone.

Python — Two-Pointer Template 
def two_pointer_template(arr: list[int]) -> None:
    left, right = 0, len(arr) - 1
    while left < right:
        # Do something with arr[left] and arr[right]
        # Then move one or both pointers:
        if # some condition:
            left += 1
        else:
            right -= 1

The Sliding Window Technique

Many array and string problems ask about a contiguous subarray or substring that satisfies some condition. The naive approach is to examine every possible subarray — O(n²). The sliding window technique solves many of these in O(n) by maintaining a "window" (a range of indices) and cleverly expanding or shrinking it.

🟣 Analogy

Imagine looking through a physical sliding window on a train. As the train moves, your window always shows a contiguous stretch of the passing landscape. You slide the window forward to see new scenery and let old scenery go. The key insight is that you do not restart from scratch each time — you just slide.

Python — Sliding Window Template 
def sliding_window_template(arr: list[int], k: int) -> int:
    # Fixed-size window of size k
    window_sum = sum(arr[:k])          # initialise first window
    best = window_sum
    for i in range(k, len(arr)):
        window_sum += arr[i] - arr[i - k]  # slide: add new, remove old
        best = max(best, window_sum)
    return best
Problem 3.1 — Maximum Subarray (Kadane's Algorithm) Beginner LeetCode ↗
Problem Statement

Given an integer array nums, find the contiguous subarray (containing at least one number) which has the largest sum, and return its sum.

Example: Input: [-2, 1, -3, 4, -1, 2, 1, -5, 4] → Output: 6 (subarray [4, -1, 2, 1])

Intuition

Imagine you are walking a path where some tiles give you points and some take them away. At each tile, you face a choice: keep going from where you are, or start fresh here if starting fresh would give you more. Kadane's algorithm formalises exactly this decision. We track the best sum ending at the current position. If continuing from the previous position would only hurt us (i.e., the running sum has gone negative), we restart from the current element.

Approach
  1. Initialise current_sum and best_sum both to the first element.
  2. Loop through the array starting from index 1.
  3. At each position, decide: extend the current subarray (current_sum + num), or start a new one (num). Take the larger.
  4. Update best_sum if current_sum just grew larger.
  5. Return best_sum.
Implementation
Python 
def max_subarray(nums: list[int]) -> int:
    """Return the maximum sum of any contiguous subarray."""
    current_sum = nums[0]  # best sum ending at current position
    best_sum    = nums[0]  # global best seen so far

    for num in nums[1:]:
        # Either extend the running subarray or start fresh here
        current_sum = max(num, current_sum + num)
        best_sum    = max(best_sum, current_sum)

    return best_sum
Line-by-Line Explanation
  • current_sum = nums[0] — We start with just the first element as our "running" subarray.
  • best_sum = nums[0] — The best we have seen so far is also just the first element.
  • for num in nums[1:] — We visit each element from the second onwards.
  • current_sum = max(num, current_sum + num) — This is the heart of the algorithm. If current_sum was negative, adding it to num would give us less than num alone. So we reset: just take num as our new starting point.
  • best_sum = max(best_sum, current_sum) — Update the global best if we just found something bigger.

Problem 3.2 — Best Time to Buy and Sell Stock Beginner LeetCode ↗
Problem Statement

You are given an array prices where prices[i] is the price of a stock on day i. You may buy on one day and sell on a later day. Return the maximum profit. If no profit is possible, return 0.

Example: Input: [7, 1, 5, 3, 6, 4] → Output: 5 (buy at 1, sell at 6)

Intuition

Track the lowest price seen so far. At each day, ask: "If I sell today, what is my profit given the cheapest purchase day I have seen?" Keep track of the best such profit.

Implementation
Python 
def max_profit(prices: list[int]) -> int:
    min_price  = float('inf')  # lowest buy price seen so far
    max_profit = 0             # best profit so far
    for price in prices:
        if price < min_price:
            min_price = price          # found a cheaper buy day
        elif price - min_price > max_profit:
            max_profit = price - min_price  # better profit found
    return max_profit

Problem 3.3 — Product of Array Except Self Intermediate LeetCode ↗
Problem Statement

Given an integer array nums, return an array answer such that answer[i] equals the product of all elements except nums[i]. You may not use division. Must run in O(n).

Example: Input: [1, 2, 3, 4] → Output: [24, 12, 8, 6]

Intuition

For position i, the answer is (product of everything to the left) × (product of everything to the right). Compute a prefix-product array in one pass, then multiply by a running suffix product in a second pass.

Implementation
Python 
def product_except_self(nums: list[int]) -> list[int]:
    n = len(nums)
    result = [1] * n

    # Pass 1: fill result[i] with the product of all elements LEFT of i
    prefix = 1
    for i in range(n):
        result[i] = prefix
        prefix *= nums[i]

    # Pass 2: multiply result[i] by product of all elements RIGHT of i
    suffix = 1
    for i in range(n - 1, -1, -1):
        result[i] *= suffix
        suffix *= nums[i]

    return result

Problem 3.4 — Longest Substring Without Repeating Characters Intermediate LeetCode ↗
Problem Statement

Given a string s, find the length of the longest substring without repeating characters.

Example: Input: "abcabcbb" → Output: 3 (substring "abc")

Intuition

Use a sliding window. Expand the right boundary one character at a time. If the new character is already inside the window, shrink the window from the left until the duplicate is gone. Use a set to track characters currently inside the window.

Implementation
Python 
def length_of_longest_substring(s: str) -> int:
    char_set = set()     # characters currently in the window
    left = 0             # left boundary of the window
    best = 0             # longest window seen

    for right in range(len(s)):
        # Shrink from left until no duplicate exists in window
        while s[right] in char_set:
            char_set.remove(s[left])
            left += 1
        char_set.add(s[right])           # add new right character
        best = max(best, right - left + 1)  # update best

    return best

Problem 3.5 — Container With Most Water Intermediate LeetCode ↗
Problem Statement

Given an array height of n non-negative integers, where each element represents a vertical line at position i with height height[i], find two lines that together with the x-axis form a container holding the most water.

Example: Input: [1,8,6,2,5,4,8,3,7] → Output: 49

Intuition

Use two pointers starting at both ends. The water held is min(height[left], height[right]) * (right - left). Always move the pointer pointing to the shorter line inward — because the width will decrease, but maybe the height will increase enough to compensate. Moving the taller line inward can never improve things.

Implementation
Python 
def max_area(height: list[int]) -> int:
    left, right = 0, len(height) - 1
    best = 0
    while left < right:
        water = min(height[left], height[right]) * (right - left)
        best = max(best, water)
        # Move the shorter wall inward (moving the taller one cannot help)
        if height[left] <= height[right]:
            left += 1
        else:
            right -= 1
    return best

Hashing — The Magic of O(1) Lookup

What if you could find any piece of information in constant time, regardless of how much data you have? That is exactly what hashing gives you — and it is one of the most powerful ideas in all of computer science.

📖 Story

Meera runs a coat-check room with 1000 hooks. Instead of searching every hook, she invents a rule: take the last 3 digits of a customer's phone number — that's their hook number. Customer 9876543210 goes to hook 210. Retrieval is instant. This is hashing: a function that maps any key to a fixed-size address, giving O(1) lookup.

Customer arrives: phone = 9876543210 Hash function: 9876543210 % 1000 = 210 Store coat at hook 210 ─────────────────────┐ ↓ Hook array: [ ][ ]...[ ][ 210 ][ ]...[ ][ ] ↑ coat stored here! Retrieval later: 9876543210 % 1000 = 210 → O(1) lookup ✓ Collision: 1876543210 also maps to hook 210 Fix: chain multiple coats at hook 210 (linked list chaining) Worst case (all collide): O(n) — but rare with a good hash fn.

Every Python dict, every set, every Counter is built on this exact idea — hook number from a formula.

The Library Index Analogy

🟣 Analogy

Imagine a library with a million books. If the books are just stacked randomly, finding the one you want means looking through all of them — O(n). But what if the library has a magical index card system: you look up the book's title, and the card instantly tells you the exact shelf and position? That is a hash map. The "magical card" is the hash function, which converts a key (the title) into an index (the shelf position) in near-constant time.

How Hash Maps Work (Under the Hood)

A hash map (called a dict in Python) stores key-value pairs. Internally, it works like this:

  1. You call a hash function on the key. This function converts the key into an integer — its "hash value."
  2. That integer is mapped to an index in an internal array using modulo arithmetic.
  3. The key-value pair is stored at that index.
  4. To look up a key later, you run the same hash function, go directly to that index, and retrieve the value.

Because this is just arithmetic (not searching), it takes O(1) on average.

What About Collisions?

Sometimes two different keys produce the same hash value — this is called a collision. Python handles this using a technique called open addressing: if the target slot is taken, it probes nearby slots until it finds an empty one. As long as the hash table is not too full, this keeps operations near O(1). In the rare worst case, all keys collide into the same slot, and lookup degrades to O(n) — but good hash functions and proper load-factor management make this extremely unlikely in practice.

📘 Note

A hash set (set in Python) is just a hash map where you only care about the keys, not the values. It supports O(1) average add, remove, and membership test. Use a set when you need to answer "have I seen this before?" and a map when you need to store associated data.

The Frequency Counting Pattern

One of the most common uses of hash maps is counting how often each element appears. This single pattern solves an enormous variety of problems.

Python — Frequency Counter Template 
from collections import Counter

def frequency_template(items: list) -> dict:
    freq = {}
    for item in items:
        freq[item] = freq.get(item, 0) + 1
    return freq

# Or use Python's built-in Counter (same result, cleaner):

    return Counter(items)
Problem 4.1 — Two Sum Beginner LeetCode ↗
Problem Statement

Given an array nums and an integer target, return the indices of the two numbers that add up to target. Exactly one solution exists.

Example: Input: nums=[2,7,11,15], target=9 → Output: [0,1]

Intuition

For each number x, we need to find its "complement" — the value target - x. Instead of searching the array for the complement (O(n) per element), we store each number we have seen in a hash map. Then the lookup is O(1).

Implementation
Python 
def two_sum(nums: list[int], target: int) -> list[int]:
    seen = {}  # maps value → index
    for i, num in enumerate(nums):
        complement = target - num
        if complement in seen:
            return [seen[complement], i]  # found the pair
        seen[num] = i  # store this number for future lookups
    return []  # no solution found

Intuition

from collections import defaultdict

def group_anagrams(strs: list[str]) -> list[list[str]]:

Problem 4.3 — Top K Frequent Elements Intermediate LeetCode ↗
Problem Statement

Given an integer array nums and an integer k, return the k most frequent elements. Order does not matter.

Example: Input: nums=[1,1,1,2,2,3], k=2 → Output: [1,2]

Intuition

Count frequencies with a hash map, then use a bucket sort trick: create an array where index i holds all numbers that appeared exactly i times. Walk from the highest bucket down, collecting elements until you have k.

Implementation
Python 
from collections import Counter

def top_k_frequent(nums: list[int], k: int) -> list[int]:
    freq = Counter(nums)           # {value: count}
    # Bucket: index = frequency, value = list of numbers with that freq
    buckets = [[] for _ in range(len(nums) + 1)]
    for num, count in freq.items():
        buckets[count].append(num)

    result = []
    for i in range(len(buckets) - 1, 0, -1):  # walk from high freq to low
        for num in buckets[i]:
            result.append(num)
            if len(result) == k:
                return result
    return result

Step 2 — bucket sort (index = frequency):

  buckets[2] = [2]

Step 3 — collect from high to low until we have k=2:

Problem 4.5 — Longest Consecutive Sequence Intermediate LeetCode ↗
Problem Statement

Given an unsorted integer array nums, find the length of the longest consecutive elements sequence. Must run in O(n).

Example: Input: [100,4,200,1,3,2] → Output: 4 (sequence: 1,2,3,4)

Intuition

Put all numbers into a set for O(1) lookup. Then, for each number, check if it is the start of a sequence (i.e., num - 1 is not in the set). If it is the start, count how far the sequence extends. Only starts trigger the inner count — so each number is visited at most twice total.

Implementation
Python 
def longest_consecutive(nums: list[int]) -> int:
    num_set = set(nums)   # O(1) membership check
    best = 0

    for num in num_set:
        if num - 1 not in num_set:   # only start sequences from their beginning
            length = 1
            while num + length in num_set:
                length += 1
            best = max(best, length)

    return best

Linked Lists

Arrays store elements in contiguous memory slots, like seats in a row. Linked lists take a completely different approach — each element lives wherever it fits in memory, but carries a note pointing to the next element. Understanding this difference unlocks a new class of problems.

📖 Story

Dev is setting up a treasure hunt for his niece. He doesn't write all the clue locations on one sheet — that would be an array. Instead, each clue envelope contains only the location of the next envelope. To find clue 5, you must open clues 1, 2, 3, 4 first — there is no shortcut. But adding a new clue anywhere is easy: just change two envelopes' directions.

Linked List: 1 → 2 → 3 → 4 → 5 → None [val:1|next:●]──→[val:2|next:●]──→[val:3|next:●]──→[val:4|next:●]──→[val:5|next:None] ↑ head Insert 99 after node 2 (O(1) once you have the pointer): Step 1: new_node.next = node2.next (new → 3) Step 2: node2.next = new_node (2 → new) [1]──→[2]──→[99]──→[3]──→[4]──→[5]──→None ↑ inserted with ZERO shifting Compare to array insert: 0 elements shifted vs n/2 on average.

Linked lists trade random access for cheap insertion — the right tool when the list changes more than it is read.

The Treasure Hunt Analogy

🟣 Analogy

Imagine a treasure hunt where the first clue is at the starting location. When you open it, it tells you where to find the second clue. The second clue tells you the location of the third, and so on. Each clue only knows about the next clue — not all of them at once. That is a linked list. The starting location is the head. Each clue is a node. The final clue says "you've reached the end" — that is None.

Singly Linked List Implementation

    def __init__(self, val: int = 0, next=None):

def build_list(values: list[int]) -> ListNode:
    dummy = ListNode(0)
    cur = dummy
    for v in values:
        cur.next = ListNode(v)
        cur = cur.next
    return dummy.next

# Helper to convert a linked list back to a Python list (for testing)
def list_to_array(head: ListNode) -> list[int]:
    result = []
    while head:
        result.append(head.val)
        head = head.next
    return result

Why Not Just Use Arrays?

Linked lists shine where arrays struggle:

  • O(1) insert/delete at the head (or any known position) — no shifting required.
  • Dynamic sizing — no pre-allocation needed.

Their weaknesses: no random access (you must traverse from the head), and extra memory for the pointer in each node.

The Fast and Slow Pointer (Runner) Technique

This clever technique uses two pointers that move through the list at different speeds — the "slow" pointer moves one step at a time, the "fast" pointer moves two. It solves cycle detection, finding the middle element, and more — all in O(n) with O(1) space.

🟣 Analogy — Floyd's Tortoise and Hare

Imagine a circular racetrack. A tortoise moves at 1 step per second. A hare moves at 2. If the track is a loop, the hare will eventually lap the tortoise and they will meet. If there is no loop, the hare will reach the end (None) without ever catching the tortoise. This is the intuition behind Floyd's cycle detection algorithm.

Problem 5.1 — Reverse a Linked List Beginner LeetCode ↗
Problem Statement

Given the head of a singly linked list, reverse the list and return the new head.

Example: 1→2→3→4→5 → 5→4→3→2→1

Intuition

Walk through the list one node at a time. For each node, flip its next pointer to point backward instead of forward. We need three pointers: prev (what came before), curr (where we are), and nxt (what comes next — saved before we overwrite).

Implementation
Python 
def reverse_list(head: ListNode) -> ListNode:
    prev = None
    curr = head
    while curr:
        nxt        = curr.next  # save next before overwriting
        curr.next  = prev       # reverse the pointer
        prev       = curr       # advance prev
        curr       = nxt        # advance curr
    return prev  # prev is the new head

    fast = head
    while fast and fast.next:
        slow = slow.next        # tortoise: 1 step
        fast = fast.next.next   # hare: 2 steps
        if slow == fast:        # they met → cycle exists
            return True
    return False  # fast hit None → no cycle

Intuition

Use two pointers with a gap of n between them. Advance both pointers together until the fast pointer reaches the end. At that point, the slow pointer is exactly at the node before the one to remove. This is a brilliant one-pass trick using the fixed-gap idea.

Implementation
Python 
def remove_nth_from_end(head: ListNode, n: int) -> ListNode:
    dummy = ListNode(0, head)
    fast = dummy
    slow = dummy

    # Advance fast n+1 steps to create a gap of n
    for _ in range(n + 1):
        fast = fast.next

    # Move both until fast reaches the end
    while fast:
        fast = fast.next
        slow = slow.next

    # slow.next is the node to remove
    slow.next = slow.next.next
    return dummy.next

Stacks

The stack is one of the simplest and most useful data structures in computer science. Its beauty lies in its constraint: you can only ever interact with the top element. This restriction, far from being a limitation, turns out to be exactly the right model for a surprising number of real-world problems.

📖 Story

Anika washes dishes at a busy restaurant. Clean plates come off the rack and go onto a stack. The waiter always picks from the TOP — the last plate washed is the first one used. If Anika needs to find the plate she washed first, she would have to unstack every single plate above it. This is a stack: you only ever see the top.

Push sequence: plate A, plate B, plate C After push(A): [A] After push(B): [B] ← top [A] After push(C): [C] ← top [B] [A] pop() → returns C remaining: [B][A] pop() → returns B remaining: [A] pop() → returns A remaining: [] LIFO: Last In, First Out. push/pop: O(1). peek (view top without removing): O(1).

Every function call in your program uses a stack internally — the call stack. Recursion is literally a stack in disguise.

The Plate Stack Analogy

🟣 Analogy

Imagine a stack of plates in a cafeteria. You can only place a new plate on top, and you can only pick up the plate on top. You cannot grab a plate from the middle without moving everything above it. This "last in, first out" (LIFO) behaviour is the defining property of a stack. The most recently added item is always the first to be removed.

In Python, we use a regular list as a stack: append() pushes onto the top, and pop() removes from the top. Both operations are O(1) amortised.

Python — Stack Basics 
stack = []
stack.append(1)   # push 1 → [1]
stack.append(2)   # push 2 → [1, 2]
stack.append(3)   # push 3 → [1, 2, 3]
top = stack[-1]   # peek at top: 3 (no removal)
val = stack.pop()  # pop: returns 3, stack → [1, 2]

The Monotonic Stack Pattern

A monotonic stack is a stack that maintains its elements in sorted order (either always increasing or always decreasing from bottom to top). As you process elements, you pop items from the stack that would violate the monotonic property before pushing the new element. This pattern solves "next greater element" and "previous smaller element" problems in O(n) — far better than the naive O(n²) approach.

Problem 6.2 — Min Stack Intermediate LeetCode ↗
Problem Statement

Design a stack that supports push, pop, top, and retrieving the minimum element in O(1) time.

Intuition

Use two stacks: one for the actual values, and one that tracks the current minimum at each level. When we push a new value, we also push the new minimum (the smaller of the new value and the current top of the min stack). When we pop, we pop from both stacks simultaneously.

Implementation
Python 
class MinStack:
    def __init__(self):
        self.stack     = []   # regular stack
        self.min_stack = []   # tracks min at each level

    def push(self, val: int) -> None:
        self.stack.append(val)
        cur_min = min(val, self.min_stack[-1] if self.min_stack else val)
        self.min_stack.append(cur_min)

    def pop(self) -> None:
        self.stack.pop()
        self.min_stack.pop()

    def top(self) -> int:
        return self.stack[-1]

    def get_min(self) -> int:
        return self.min_stack[-1]

def daily_temperatures(temps: list[int]) -> list[int]:

            idx = stack.pop()
            result[idx] = i - idx  # days until warmer

We use a monotonic increasing stack: when we encounter a bar shorter than the top of the stack, the top bar can no longer extend right. Pop it and compute its maximum area using the remaining stack top to determine its left boundary.

Implementation
Python 
def largest_rectangle(heights: list[int]) -> int:
    stack  = []   # monotonic increasing stack of (index, height)
    best   = 0
    heights.append(0)  # sentinel: force all bars to be popped at the end

    for i, h in enumerate(heights):
        start = i
        while stack and stack[-1][1] > h:
            idx, height = stack.pop()
            best  = max(best, height * (i - idx))
            start = idx   # can extend left to where the popped bar started
        stack.append((start, h))

    heights.pop()   # restore original array
    return best

Queues and Deques

If a stack is a pile of plates, a queue is a line of people waiting at a ticket counter. The first person to arrive is the first to be served. This simple principle — first in, first out — is the backbone of level-order traversal, shortest path algorithms, and more.

📖 Story

It is 8am at the coffee shop. Customers line up in the order they arrive. The barista serves from the FRONT. New customers join at the BACK. Customer 1 (who arrived first) gets their coffee first — no matter who joins the queue later. Nobody cuts. Nobody gets skipped. This fairness is the entire point of a queue.

Customers arrive: Alice → Bob → Carol → Dave enqueue(Alice): [Alice] enqueue(Bob): [Alice, Bob] enqueue(Carol): [Alice, Bob, Carol] enqueue(Dave): [Alice, Bob, Carol, Dave] ↑ front ↑ back dequeue() → Alice [Bob, Carol, Dave] dequeue() → Bob [Carol, Dave] FIFO: First In, First Out. enqueue/dequeue: O(1) with collections.deque BFS uses a queue: visit Alice's neighbours before their neighbours.

Queues appear everywhere fairness matters: print spoolers, OS scheduling, BFS graph traversal — all queues.

Queue: First In, First Out (FIFO)

🟣 Analogy

Imagine people lining up to buy concert tickets. The first person who arrived waits at the front. New arrivals join at the back. When a ticket window opens, the person at the front is served. No cutting in line! This is FIFO. In computing, queues are used for task scheduling, print spoolers, BFS graph traversal, and any scenario where fairness of processing order matters.

📘 Why Not Use a Regular List for Queues?

Python's list.pop(0) removes the first element but has to shift every remaining element one position to the left — that is O(n). A collections.deque uses a doubly-linked internal structure so popleft() is O(1). Always use deque for queues.

Deque: Double-Ended Queue

A deque (pronounced "deck") allows O(1) add and remove from both ends. This makes it a generalisation of both stacks and queues, and it is particularly powerful for the "sliding window maximum" problem.

Problem 7.1 — Number of Islands (BFS Version) Intermediate LeetCode ↗
Problem Statement

Given a 2D grid of '1' (land) and '0' (water), count the number of islands. An island is surrounded by water and formed by connecting adjacent land cells horizontally or vertically.

Example: Grid with two clusters of 1s → Output: 2

Intuition

Think of it as a flood-fill. When you discover a land cell, use BFS to "flood" (mark as visited) all connected land cells. Each time you start a new flood from an unvisited land cell, you have found a new island. Count how many floods you initiate.

Implementation
Python 
from collections import deque

def num_islands(grid: list[list[str]]) -> int:
    if not grid: return 0
    rows, cols = len(grid), len(grid[0])
    count = 0

    def bfs(r, c):
        queue = deque([(r, c)])
        grid[r][c] = '0'  # mark visited immediately on enqueue
        while queue:
            row, col = queue.popleft()
            for dr, dc in [(1,0),(-1,0),(0,1),(0,-1)]:
                nr, nc = row + dr, col + dc
                if 0 <= nr < rows and 0 <= nc < cols and grid[nr][nc] == '1':
                    grid[nr][nc] = '0'
                    queue.append((nr, nc))

    for r in range(rows):
        for c in range(cols):
            if grid[r][c] == '1':
                bfs(r, c)
                count += 1
    return count

Problem 7.2 — Sliding Window Maximum Advanced LeetCode ↗
Problem Statement

Given an array nums and window size k, return a list of the maximum value in each window of size k as it slides across the array.

Example: nums=[1,3,-1,-3,5,3,6,7], k=3 → [3,3,5,5,6,7]

Intuition

Use a monotonic deque that stores indices in decreasing order of their values. When we slide the window: (1) remove indices from the front that are outside the window; (2) remove indices from the back whose values are smaller than the current value (they can never be the maximum while the current element is in the window). The front of the deque always holds the maximum.

Implementation
Python 
from collections import deque

def max_sliding_window(nums: list[int], k: int) -> list[int]:
    dq     = deque()   # stores indices, values are decreasing
    result = []

    for i, num in enumerate(nums):
        # Remove elements outside the window from the front
        while dq and dq[0] < i - k + 1:
            dq.popleft()
        # Remove smaller elements from the back (they'll never be max)
        while dq and nums[dq[-1]] < num:
            dq.pop()
        dq.append(i)
        # The front of deque is the max of the current window
        if i >= k - 1:
            result.append(nums[dq[0]])

    return result

from collections import deque

def level_order(root) -> list[list[int]]:
    if not root: return []
    result = []
    queue  = deque([root])

    while queue:
        level_size = len(queue)   # nodes in the current level
        level = []
        for _ in range(level_size):
            node = queue.popleft()
            level.append(node.val)
            if node.left:  queue.append(node.left)
            if node.right: queue.append(node.right)
        result.append(level)

    return result

Given a stream of characters, at each step, find the first non-repeating character. Return '#' if none exists.

Example: Stream "aabcde" → at each step: ['a','#','b','b','b','c']

Intuition

Maintain a queue of characters seen in order, and a frequency map. When asked for the first non-repeating character, drain the front of the queue until you find a character with frequency 1.

Implementation
Python 
from collections import deque, defaultdict

def first_non_repeating_stream(stream: str) -> list[str]:
    freq  = defaultdict(int)
    queue = deque()
    result = []

    for ch in stream:
        freq[ch] += 1
        queue.append(ch)
        # Remove repeated characters from the front
        while queue and freq[queue[0]] > 1:
            queue.popleft()
        result.append(queue[0] if queue else '#')

    return result

Trees and Binary Trees

Arrays and linked lists store data in a line. Trees break that constraint and let data branch in multiple directions — opening up an entirely new class of problems and solutions. Once you understand trees, graphs, heaps, and many other structures become much easier to grasp.

The Family Tree Analogy

🟣 Analogy

Think of a family tree. You start at a single ancestor at the top — the root. Each person can have children. Each child can have their own children. There are no cycles (you cannot be your own ancestor). The people with no children are called leaves. The number of connections between a person and the root is their depth. This is exactly how a tree data structure works.

📖 Story

Leena is drawing her family tree for a school project. She puts her great-grandmother at the top — the root. Below are her children (Leena's great-aunts and great-uncles). Each of them has children, and so on. Leena is somewhere near the bottom, a leaf — she has no children on this tree yet. Every person knows only their parent and their own children, not their cousins directly.

Family Tree (Binary Tree example): Asha (root, depth=0) / \ Bina Chandra (depth=1) / \ \ Diya Eesha Farhan (depth=2) (leaf) (leaf) (leaf) Height of tree = 2 (longest root→leaf path) Bina's subtree = {Bina, Diya, Eesha} Binary rule: each node has AT MOST 2 children (left, right). Recursion rule: every subtree is itself a valid tree.

Every tree algorithm — inorder, BFS, DFS — is really just a recipe for visiting this family in a specific order.

Tree Vocabulary

  • Root: The single top-most node. Every tree has exactly one root.
  • Parent / Child: If node A points to node B, A is B's parent and B is A's child.
  • Leaf: A node with no children.
  • Height: The longest path from a node down to a leaf.
  • Depth: The distance from the root to a given node.
  • Subtree: Any node and all its descendants form a valid subtree.

Binary Tree: At Most Two Children

A binary tree is a tree where every node has at most two children — conventionally called left and right. This seemingly simple constraint unlocks elegant recursive algorithms.

Traversal means visiting every node exactly once. There are four canonical ways to traverse a binary tree, each with a different visit order:

from collections import deque
from typing import Optional, List

# Recursive DFS traversals
def inorder(root: Optional[TreeNode]) -> List[int]:
    if not root: return []
    return inorder(root.left) + [root.val] + inorder(root.right)

def preorder(root: Optional[TreeNode]) -> List[int]:
    if not root: return []
    return [root.val] + preorder(root.left) + preorder(root.right)

def postorder(root: Optional[TreeNode]) -> List[int]:
    if not root: return []
    return postorder(root.left) + postorder(root.right) + [root.val]

# Iterative level-order (BFS)
def level_order_flat(root: Optional[TreeNode]) -> List[int]:
    if not root: return []
    result, q = [], deque([root])
    while q:
        node = q.popleft()
        result.append(node.val)
        if node.left:  q.append(node.left)
        if node.right: q.append(node.right)
    return result

Intuition

def max_depth(root: Optional[TreeNode]) -> int:

Implementation
Python 
def diameter_of_binary_tree(root: Optional[TreeNode]) -> int:
    best = [0]  # use a list so inner function can mutate it

        if not node: return 0
        left  = height(node.left)
        right = height(node.right)
        best[0] = max(best[0], left + right)  # diameter through this node
        return 1 + max(left, right)           # height for parent

    return best[0]

Binary Search Trees

A binary search tree is a binary tree with a superpower: its structure enforces a sorted ordering across the entire tree. This single constraint — every left descendant is smaller, every right descendant is larger — makes search, insert, and delete all run in O(log n) for balanced trees.

🟣 Analogy

Imagine a phone book. Because names are sorted alphabetically, you never start from page 1 and flip every page. You open roughly in the middle, decide whether your target is in the left or right half, and repeat. A Binary Search Tree is this exact intuition encoded in a tree: every node is a "pivot" that routes you left (smaller) or right (larger) until you arrive at your answer — or discover it does not exist.

📖 Story

Rahul is a librarian who invented a brilliant filing system. Every shelf has a "pivot" book in the middle. Books with titles earlier in the alphabet go LEFT. Books later in the alphabet go RIGHT. Each half-shelf follows the same rule, recursively. Now when someone asks for "Pride and Prejudice", Rahul never looks at more than log₂(n) shelves — because at each step he eliminates half the remaining books.

BST with values: insert 8, 3, 10, 1, 6, 14, 4, 7 8 ← root: left < 8 < right / \ 3 10 ← 3 < 8, 10 > 8 / \ \ 1 6 14 ← 1<3, 6>3, 14>10 / \ 4 7 ← 4<6, 7>6 Search for 7: Start at 8 → 7 < 8 → go left to 3 3 → 7 > 3 → go right to 6 6 → 7 > 6 → go right to 7 ✓ (3 comparisons, not 7)

A balanced BST gives you O(log n) search, insert, and delete — making it the sorted array's faster, dynamic cousin.

The BST Property

📘 The BST Invariant

For every node X in a BST:
• All nodes in X's left subtree have values strictly less than X's value.
• All nodes in X's right subtree have values strictly greater than X's value.
• This property holds recursively for every subtree.

       / \
      3   10
     / \    \
    1   6    14
       / \   /
      4   7 13

Inorder traversal: 1, 3, 4, 6, 7, 8, 10, 13, 14  ← sorted!

Search, Insert, and Delete

Python — BST Search and Insert 
def search_bst(root: Optional[TreeNode], val: int) -> Optional[TreeNode]:
    if not root or root.val == val:
        return root
    if val < root.val:
        return search_bst(root.left,  val)
    return     search_bst(root.right, val)

def insert_bst(root: Optional[TreeNode], val: int) -> TreeNode:
    if not root: return TreeNode(val)  # found insertion spot
    if val < root.val:
        root.left  = insert_bst(root.left,  val)
    else:
        root.right = insert_bst(root.right, val)
    return root

Problem Statement

Given the root of a binary tree, determine if it is a valid BST.

Intuition

A common mistake is only checking the immediate parent–child relationship. But a BST must satisfy the property for the entire subtree. The correct approach: pass down a valid range [min_val, max_val] for each node. The root can be anything (−∞, +∞). Going left tightens the upper bound; going right tightens the lower bound.

Implementation
Python 
def is_valid_bst(root: Optional[TreeNode]) -> bool:
    def validate(node, low: float, high: float) -> bool:
        if not node: return True
        if not (low < node.val < high): return False
        return (validate(node.left,  low,      node.val) and
                validate(node.right, node.val, high))

    return validate(root, float('-inf'), float('inf'))

Problem 9.2 — Lowest Common Ancestor of a BST Intermediate LeetCode ↗

Given a BST and two nodes p and q, find their lowest common ancestor (LCA) — the deepest node that has both as descendants.

Implementation
Python 
def lowest_common_ancestor(root: TreeNode, p: TreeNode, q: TreeNode) -> TreeNode:
    while root:
        if p.val < root.val and q.val < root.val:
            root = root.left       # both smaller → go left
        elif p.val > root.val and q.val > root.val:
            root = root.right      # both larger → go right
        else:
            return root            # split point = LCA

Given the root of a BST and an integer k, return the kth smallest element.

Implementation
Python 
def kth_smallest(root: Optional[TreeNode], k: int) -> int:
    stack, node = [], root
    while stack or node:
        while node:                 # go as far left as possible
            stack.append(node)
            node = node.left
        node = stack.pop()           # visit this node (inorder)
        k -= 1
        if k == 0: return node.val  # found the kth smallest
        node = node.right            # move to right subtree

Heaps and Priority Queues

Imagine a queue where, instead of serving the person who waited longest, you always serve the person with the highest priority. That is exactly what a heap provides — and it makes "find the minimum" or "find the maximum" extremely efficient.

📖 Story

Sonia is the hospital triage nurse. She doesn't treat patients in arrival order — she treats the most critical first, always. When a new patient arrives, she slots them into the right position instantly. The moment the most critical patient is treated, the next most critical automatically rises to the top. This self-organising priority system is a min-heap.

Min-Heap (smallest = highest priority, severity scores: 9,4,7,2,5): Insert 9: [9] Insert 4: [4] ← 4<9, swap up (heapify up) [9] Insert 7: [4] ← 7>4, stays [9][7] Insert 2: [2] ← 2<4, bubble up to root [4][7] [9] Insert 5: [2] [4][7] [9][5] ← 5>4, stays extract_min() → removes 2, last element moves to root, sifts down: [4] [5][7] [9] heappush: O(log n) heappop: O(log n) peek min: O(1)

Whenever a problem says "always give me the k-th smallest/largest," your first instinct should be: heap.

What Is a Heap?

🟣 Analogy

Picture a hospital emergency room. Patients are not seen in the order they arrived — the most critically ill patient is always seen first. When a new critical patient arrives, they jump to the front. When the most critical patient leaves, the next-most-critical takes their place. The structure maintaining this ordering is a heap.

A min-heap always keeps the smallest element at the top. A max-heap keeps the largest. In Python, the built-in heapq module implements a min-heap. To simulate a max-heap, negate all values.

Problem Statement

Given an integer array nums and integer k, return the kth largest element.

Example: [3,2,1,5,6,4], k=2 → 5

Intuition

Maintain a min-heap of size k. As you scan the array, push each element. If the heap grows beyond k, pop the minimum. At the end, the smallest element in the heap is the kth largest overall — it survived by being larger than everything that was ejected.

Implementation
Python 
import heapq

def find_kth_largest(nums: list[int], k: int) -> int:
    heap = []
    for num in nums:
        heapq.heappush(heap, num)
        if len(heap) > k:
            heapq.heappop(heap)   # evict the smallest — it's not top-k
    return heap[0]               # smallest of the top-k = kth largest

Problem 10.2 — Merge K Sorted Lists Advanced LeetCode ↗
Problem Statement

You are given k sorted linked lists. Merge them all into one sorted linked list.

Intuition

Use a min-heap initialised with the first node from each list. Repeatedly pop the minimum node, add it to the result, then push its successor (if any) onto the heap. The heap always contains at most k elements — the "front runners" from each list.

Implementation
Python 
import heapq
from typing import List, Optional

def merge_k_lists(lists: List[Optional[ListNode]]) -> Optional[ListNode]:
    heap = []
    # Seed the heap with the head of each non-empty list
    # Tuple: (node_value, list_index, node) — list_index breaks ties
    for i, node in enumerate(lists):
        if node:
            heapq.heappush(heap, (node.val, i, node))

    dummy = ListNode(0)
    tail  = dummy
    while heap:
        val, i, node = heapq.heappop(heap)
        tail.next = node
        tail = tail.next
        if node.next:
            heapq.heappush(heap, (node.next.val, i, node.next))

    return dummy.next

Problem 10.3 — Find Median from Data Stream Advanced LeetCode ↗
Problem Statement

Design a data structure that accepts a stream of integers and, after each insertion, can return the current median in O(1) time. Insertion should be O(log n).

Intuition

Split the numbers into two halves: a max-heap holding the smaller half, and a min-heap holding the larger half. Keep them balanced (sizes differ by at most 1). The median is the top of the larger half (odd count) or the average of the two tops (even count).

Implementation
Python 
import heapq

class MedianFinder:
    def __init__(self):
        self.lo = []   # max-heap (negate values) — smaller half
        self.hi = []   # min-heap — larger half

    def add_num(self, num: int) -> None:
        heapq.heappush(self.lo, -num)            # always push to lo first
        heapq.heappush(self.hi, -heapq.heappop(self.lo))  # balance: move max(lo) to hi
        if len(self.hi) > len(self.lo):          # keep lo >= hi in size
            heapq.heappush(self.lo, -heapq.heappop(self.hi))

    def find_median(self) -> float:
        if len(self.lo) > len(self.hi):
            return float(-self.lo[0])
        return (-self.lo[0] + self.hi[0]) / 2.0

Graphs

Trees are restricted graphs — they have no cycles and a single root. Graphs are the fully general version: nodes connected by edges, with no restrictions on structure. They model road networks, social connections, dependencies, and more. Understanding graphs unlocks a vast category of real-world problems.

Your GPS finds the shortest path (Dijkstra), and a bridge-finding algorithm tells you which road, if closed, disconnects the city. Graphs are simply the mathematical abstraction of any network — roads, friendships, web pages, or task dependencies.

Graph Vocabulary

  • Vertex (Node): A single entity in the graph.

from collections import deque

def bfs(graph: dict, start: int) -> list[int]:

    order   = []

        order.append(node)
        for neighbour in graph[node]:
            if neighbour not in visited:
                visited.add(neighbour)
                queue.append(neighbour)

    return order
Problem 11.1 — Number of Connected Components Intermediate LeetCode ↗ (Premium)
Problem Statement

Given n nodes labelled 0 to n-1 and a list of undirected edges, count the number of connected components.

Intuition

Use Union-Find (Disjoint Set Union). For each edge, union the two endpoints. Count the number of distinct roots at the end.

Implementation
Python — Union-Find 
def count_components(n: int, edges: list[list[int]]) -> int:
    parent = list(range(n))
    rank   = [0] * n

    def find(x):
        if parent[x] != x:
            parent[x] = find(parent[x])  # path compression
        return parent[x]

    def union(x, y) -> bool:
        rx, ry = find(x), find(y)
        if rx == ry: return False   # already in same component
        if rank[rx] < rank[ry]: rx, ry = ry, rx
        parent[ry] = rx
        if rank[rx] == rank[ry]: rank[rx] += 1
        return True

    components = n
    for u, v in edges:
        if union(u, v):
            components -= 1   # merged two components
    return components

Problem 11.2 — Course Schedule (Cycle Detection / Topological Sort) Intermediate LeetCode ↗
Problem Statement

Intuition

This is cycle detection in a directed graph. If there is a cycle in the prerequisite graph, you can never finish all courses (A requires B requires A). Use DFS with three states: unvisited (0), in-progress (1), done (2). If you revisit a node that is in-progress, you have found a cycle.

Implementation
Python 
def can_finish(num_courses: int, prerequisites: list[list[int]]) -> bool:
    graph = defaultdict(list)
    for a, b in prerequisites:
        graph[b].append(a)  # b must be taken before a

    state = [0] * num_courses   # 0=unvisited, 1=in-progress, 2=done

    def has_cycle(node) -> bool:
        if state[node] == 1: return True   # back edge → cycle!
        if state[node] == 2: return False  # already fully explored
        state[node] = 1
        for nb in graph[node]:
            if has_cycle(nb): return True
        state[node] = 2
        return False

    return not any(has_cycle(c) for c in range(num_courses))

class GraphNode:

        self.val        = val
        self.neighbours = neighbours if neighbours else []

def clone_graph(node: Optional[GraphNode]) -> Optional[GraphNode]:
    if not node: return None
    cloned = {}   # original node → cloned node

    def dfs(n):
        if n in cloned: return cloned[n]  # already cloned
        copy = GraphNode(n.val)
        cloned[n] = copy
        for nb in n.neighbours:
            copy.neighbours.append(dfs(nb))
        return copy

    return dfs(node)

from collections import deque

def ladder_length(beginWord: str, endWord: str, wordList: list[str]) -> int:
    word_set = set(wordList)
    if endWord not in word_set: return 0

    queue = deque([(beginWord, 1)])  # (word, path_length)
    visited = {beginWord}

    while queue:
        word, length = queue.popleft()
        for i in range(len(word)):
            for c in 'abcdefghijklmnopqrstuvwxyz':
                next_word = word[:i] + c + word[i+1:]
                if next_word == endWord:
                    return length + 1
                if next_word in word_set and next_word not in visited:
                    visited.add(next_word)
                    queue.append((next_word, length + 1))
    return 0  # no path found

Sorting Algorithms

Sorting is one of the most studied problems in computer science — and for good reason. A sorted array unlocks binary search, simplifies duplicate detection, and is a prerequisite to countless other algorithms. Understanding how sorting works at a deep level reveals profound ideas about algorithmic design.

🟣 Analogy

Imagine you are handed 52 shuffled playing cards and asked to sort them. You might scan for the lowest card, pull it out, and repeat — that is Selection Sort. Or you might pick up cards one by one and slide each into the correct position among the cards already in your hand — that is Insertion Sort. Merge Sort is like splitting the deck in half, asking two friends to each sort their half, then carefully merging the two sorted halves. Every sorting algorithm is a different strategy for the same familiar task; the differences lie in how many comparisons and swaps they require.

📖 Story

Vikram is dealt 7 playing cards face-down. He flips them one by one and slots each into the right position among the cards already in his hand — that's Insertion Sort. His friend Divya splits her 7 cards into two piles, sorts each pile separately, then carefully merges them — that's Merge Sort. Same result. Wildly different effort. One is O(n²). The other is O(n log n). At 7 cards it doesn't matter. At 7 million database rows, it's 1 second vs 3 hours.

Merge Sort — The Divide-and-Conquer Classic

Merge Sort splits the array in half, recursively sorts each half, then merges the two sorted halves. The key insight is that merging two sorted lists takes O(n). The recursion depth is O(log n). Total: O(n log n) — guaranteed, regardless of input.

Python — Merge Sort 
def merge_sort(arr: list[int]) -> list[int]:
    if len(arr) <= 1:
        return arr   # base case: single element is already sorted

    mid   = len(arr) // 2
    left  = merge_sort(arr[:mid])    # sort left half
    right = merge_sort(arr[mid:])    # sort right half

    # Merge two sorted halves
    result = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i]);  i += 1
        else:
            result.append(right[j]); j += 1
    result.extend(left[i:])
    result.extend(right[j:])
    return result

Quick Sort — The In-Place Speed Demon

Quick Sort picks a pivot, partitions the array so everything smaller is to the pivot's left and everything larger is to its right, then recursively sorts both sides. With a good pivot choice (like randomised), the average case is O(n log n) with O(log n) space — much better in practice than merge sort's O(n) extra space.

Python — Quick Sort 
import random

def quick_sort(arr: list[int], lo: int, hi: int) -> None:
    if lo >= hi: return   # base case

    # Randomise pivot to avoid O(n²) on sorted input
    pivot_idx = random.randint(lo, hi)
    arr[pivot_idx], arr[hi] = arr[hi], arr[pivot_idx]
    pivot = arr[hi]

    i = lo - 1  # pointer to last element <= pivot
    for j in range(lo, hi):
        if arr[j] <= pivot:
            i += 1
            arr[i], arr[j] = arr[j], arr[i]

    arr[i + 1], arr[hi] = arr[hi], arr[i + 1]   # place pivot
    pivot_pos = i + 1

    quick_sort(arr, lo,           pivot_pos - 1)
    quick_sort(arr, pivot_pos + 1, hi)

Problem Statement

Given a list of intervals [start, end], merge all overlapping intervals and return the result.

def merge_intervals(intervals: list[list[int]]) -> list[list[int]]:
    intervals.sort(key=lambda x: x[0])  # sort by start time
    merged = [intervals[0]]

    for start, end in intervals[1:]:
        if start <= merged[-1][1]:         # overlaps last merged interval
            merged[-1][1] = max(merged[-1][1], end)  # extend
        else:
            merged.append([start, end])     # new separate interval
    return merged

Binary Search

Binary search is the art of discarding half the search space at every step. Applied to a sorted array, it finds any element in O(log n) time. Applied more broadly, it solves a whole category of optimisation problems where the answer can be "guessed" and verified cheaply.

📖 Story

Anjali is playing "guess the number" — you think of a number 1–1000, she guesses. A bad player guesses 1, 2, 3, 4... taking up to 1000 guesses. Anjali always guesses 500 first. You say "higher." She guesses 750. "Lower." She guesses 625. She finds any number in at most 10 guesses. This is binary search: each guess eliminates half the remaining possibilities.

🟣 Analogy

Think of a "high-low" guessing game. Your friend thinks of a number between 1 and 100. You guess 50. They say "lower." You guess 25. They say "higher." You guess 37... You will always find the answer in at most 7 guesses (log₂ 100 ≈ 7). Binary search is this game, made precise.

Python — Three Binary Search Templates 
# Template 1: Exact match
def binary_search(nums: list[int], target: int) -> int:
    lo, hi = 0, len(nums) - 1
    while lo <= hi:
        mid = lo + (hi - lo) // 2   # avoids integer overflow
        if   nums[mid] == target: return mid
        elif nums[mid] <  target: lo = mid + 1
        else:                     hi = mid - 1
    return -1

# Template 2: Leftmost insertion point (first element >= target)
def lower_bound(nums: list[int], target: int) -> int:
    lo, hi = 0, len(nums)    # hi = len(nums) for "beyond last" result
    while lo < hi:
        mid = (lo + hi) // 2
        if nums[mid] < target: lo = mid + 1
        else:                  hi = mid
    return lo

# Template 3: Search on answer space (binary search on the result)
def search_answer_space(lo: int, hi: int) -> int:
    while lo < hi:
        mid = (lo + hi) // 2
        if feasible(mid):   # feasible() returns True if mid satisfies the condition
            hi = mid
        else:
            lo = mid + 1
    return lo            # lo == hi == the smallest feasible answer

Recursion and Backtracking

Recursion is a function calling itself to solve a smaller version of the same problem. Backtracking is recursion applied to exploration — you try a path, and if it fails, you undo your last choice and try another. Together, they solve every "generate all possibilities" problem.

🟣 Analogy

Recursion is like a set of Russian nesting dolls (Matryoshka). Each doll contains a slightly smaller version of itself, until you reach the smallest doll — the base case — which has nothing inside. To count the total dolls you open one, count it, then solve the same problem on the smaller doll inside. Backtracking adds a twist: imagine navigating a maze. At each fork you mark the path you took, explore it fully, and if it leads to a dead end you erase the mark and try the other fork. That erasure is the "undo" step — and it is what makes backtracking both elegant and powerful.

📖 Story

Kiran is exploring a maze. At every fork he marks the path he chose with chalk and walks forward. If he hits a dead end, he erases the chalk and backtracks to the last fork, tries the next direction. He never visits the same dead-end twice. When he finds the exit, he stops. Backtracking is exactly this: try, mark, explore, undo, try the next option.

Maze as a decision tree (generating subsets of [1,2,3]): Start: [] ├─ include 1: [1] │ ├─ include 2: [1,2] │ │ ├─ include 3: [1,2,3] ✓ record │ │ └─ skip 3: [1,2] ✓ record │ └─ skip 2: [1] │ ├─ include 3: [1,3] ✓ record │ └─ skip 3: [1] ✓ record └─ skip 1: [] ├─ include 2: [2] │ ├─ include 3: [2,3] ✓ record │ └─ skip 3: [2] ✓ record └─ skip 2: [] └─ include 3: [3] ✓ record ... []:✓ result = [[1,2,3],[1,2],[1,3],[1],[2,3],[2],[3],[]] ← 2³=8 subsets Chalk = adding to path. Erasing = path.pop() (the backtrack step).

Every "generate all" problem — subsets, permutations, combinations, N-Queens — is this same tree walk.

The Universal Backtracking Template

📘 Choose → Explore → Unchoose

Every backtracking problem follows the same three-step loop:
1. Choose: Pick a candidate from the available choices.
2. Explore: Recurse with that candidate added to the current path.
3. Unchoose: Remove the candidate after the recursion returns (backtrack to the previous state).

Python — Backtracking Template 
def backtrack(path: list, choices: list, result: list) -> None:
    if is_solution(path):
        result.append(list(path))   # save a copy, not a reference!
        return

    for choice in choices:
        if is_valid(choice, path):
            path.append(choice)       # Choose
            backtrack(path, next_choices(choices, choice), result)  # Explore
            path.pop()                # Unchoose (backtrack)

def permutations(nums: list[int]) -> list[list[int]]:
    result = []
    used   = [False] * len(nums)

    def backtrack(path: list[int]):
        if len(path) == len(nums):
            result.append(list(path))
            return
        for i, num in enumerate(nums):
            if used[i]: continue
            used[i] = True
            path.append(num)        # choose
            backtrack(path)         # explore
            path.pop()              # unchoose
            used[i] = False

    backtrack([])
    return result

        return found

Dynamic Programming

Dynamic programming (DP) is the most intellectually rich topic in DSA — and the most feared. But underneath the intimidating name is a simple idea: if you are solving the same subproblem over and over, remember the answer instead of computing it again. This one insight transforms exponential-time recursion into polynomial-time solutions.

🟣 Analogy

Imagine you are climbing a staircase and a friend asks you how many ways you can reach step 10. Instead of counting all paths from scratch, you realise: "I already know the answer for steps 8 and 9 — step 10 is just the sum of those." That is Dynamic Programming in a nutshell — solve a big problem by combining the already-known answers to smaller overlapping sub-problems, storing each result so you never compute it twice. It is the difference between a naïve recursive explorer who revisits the same dead-ends over and over, and a methodical cartographer who fills in a map one cell at a time.

📖 Story

Zara is climbing a staircase, 1 or 2 steps at a time. Her friend asks: "How many ways to reach step 5?" Zara starts computing and notices she keeps re-solving the same sub-questions. "How many ways to reach step 3?" comes up over and over inside different branches of her recursion. She writes the answers in a notebook. Now each answer is computed exactly once and looked up instantly. That notebook is the DP table.

Ways to climb n steps (1 or 2 steps at a time): Naive recursion tree for n=5: ways(5) = ways(4) + ways(3) ← 2 calls = [ways(3)+ways(2)] + [ways(2)+ways(1)] ← ways(3) called TWICE ... ways(2) called 3 times, ways(1) called 5 times DP (memoised notebook): step 0: 1 way ← base case step 1: 1 way (only from step 0: +1) step 2: 2 ways (from 0: +2 | from 1: +1) step 3: 3 ways dp[3] = dp[2] + dp[1] = 2+1 step 4: 5 ways dp[4] = dp[3] + dp[2] = 3+2 step 5: 8 ways dp[5] = dp[4] + dp[3] = 5+3 ✓ Each sub-answer computed ONCE. Total: O(n) time, O(1) space.

The two signals for DP: (1) overlapping subproblems — same question answered repeatedly; (2) optimal substructure — the best answer uses the best sub-answers.

The Two Conditions for DP

A problem is a candidate for dynamic programming if and only if it has both of these properties:

  1. Overlapping subproblems: The recursive solution solves the same subproblem multiple times. (If every subproblem is unique, divide-and-conquer is sufficient.)
  2. Optimal substructure: The optimal solution to the full problem can be constructed from optimal solutions to its subproblems.

Problem 15.1 — Climbing Stairs Beginner LeetCode ↗
Problem Statement

You are climbing n stairs. Each time you can climb 1 or 2 steps. How many distinct ways can you reach the top?

Example: n=4 → 5 ways

Intuition

To reach stair n, you must have come from stair n-1 (one step) or stair n-2 (two steps). So ways(n) = ways(n-1) + ways(n-2). This is exactly the Fibonacci recurrence. Base cases: ways(1)=1, ways(2)=2.

Implementation
Python — Bottom-Up DP 
def climb_stairs(n: int) -> int:
    if n <= 2: return n
    a, b = 1, 2   # ways(1), ways(2)
    for _ in range(3, n + 1):
        a, b = b, a + b   # slide the window forward
    return b

Climbing Stairs is the Fibonacci recurrence in disguise: f(n) = f(n-1) + f(n-2). You only ever need the two previous values, reducing space from O(n) to O(1). Recognise this pattern whenever a DP recurrence depends only on the last two states.

Problem 15.2 — House Robber Beginner LeetCode ↗
Problem Statement

You are a thief. Houses are arranged in a row; each has some money. You cannot rob two adjacent houses (the alarm triggers). Maximise the total money you can rob.

Example: [2,7,9,3,1] → 12 (rob house 0, 2, 4)

Intuition

At house i, choose: rob it (get nums[i] + best_up_to[i-2]) or skip it (get best_up_to[i-1]). Take the maximum. Only two previous values are needed.

Implementation
Python 
def rob(nums: list[int]) -> int:
    prev2, prev1 = 0, 0   # best up to i-2, best up to i-1
    for num in nums:
        curr  = max(prev1, prev2 + num)  # skip or rob current house
        prev2, prev1 = prev1, curr
    return prev1

Problem 15.3 — Coin Change Intermediate LeetCode ↗
Problem Statement

Given coin denominations and a target amount, find the minimum number of coins needed to make up the amount. Return -1 if impossible.

Example: coins=[1,5,6,9], amount=11 → 2 (5+6)

Intuition

Classic unbounded knapsack. dp[i] = minimum coins to make amount i. For each amount, try every coin denomination: dp[i] = min(dp[i], dp[i - coin] + 1). Base case: dp[0] = 0.

Implementation
Python 
def coin_change(coins: list[int], amount: int) -> int:
    INF = amount + 1           # sentinel: more than any valid answer
    dp  = [INF] * (amount + 1)
    dp[0] = 0                   # base case: 0 coins to make amount 0

    for i in range(1, amount + 1):
        for coin in coins:
            if coin <= i:
                dp[i] = min(dp[i], dp[i - coin] + 1)

    return dp[amount] if dp[amount] < INF else -1

Problem 15.4 — Longest Common Subsequence Intermediate LeetCode ↗
Problem Statement

Given two strings text1 and text2, find the length of their longest common subsequence.

Example: text1="abcde", text2="ace" → 3 (LCS = "ace")

Intuition

2D DP. dp[i][j] = LCS of text1[:i] and text2[:j]. If the characters match: dp[i][j] = dp[i-1][j-1] + 1. If not: dp[i][j] = max(dp[i-1][j], dp[i][j-1]) — skip one character from either string.

Implementation
Python 
def lcs(text1: str, text2: str) -> int:
    m, n = len(text1), len(text2)
    dp = [[0] * (n + 1) for _ in range(m + 1)]

    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if text1[i-1] == text2[j-1]:
                dp[i][j] = dp[i-1][j-1] + 1   # characters match
            else:
                dp[i][j] = max(dp[i-1][j], dp[i][j-1])

    return dp[m][n]

Problem 15.5 — 0/1 Knapsack (Partition Equal Subset Sum) Intermediate LeetCode ↗
Problem Statement

Given an integer array, determine if it can be partitioned into two subsets with equal sum.

Example: [1,5,11,5] → True (subsets [1,5,5] and [11])

Intuition

Total sum must be even. Then the question becomes: can we find a subset summing to total/2? This is the classic 0/1 knapsack. Use a boolean DP array where dp[s] = True if sum s is achievable. Process in reverse to avoid counting the same item twice.

Implementation
Python 
def can_partition(nums: list[int]) -> bool:
    total = sum(nums)
    if total % 2: return False   # odd total → impossible
    target = total // 2

    dp = [False] * (target + 1)
    dp[0] = True   # base case: empty subset sums to 0

    for num in nums:
        for s in range(target, num - 1, -1):  # traverse backwards: 0/1 knapsack
            dp[s] = dp[s] or dp[s - num]

    return dp[target]

Time: O(n × target). Space: O(target).

Key Takeaway

The 0/1 knapsack traverses the capacity backwards to ensure each item is only counted once. If you traverse forward, you get the unbounded knapsack (items can be reused).

Problem 15.6 — Unique Paths Beginner LeetCode ↗
Problem Statement

A robot is in the top-left corner of an m × n grid. It can only move right or down. How many unique paths reach the bottom-right corner?

Implementation
Python 
def unique_paths(m: int, n: int) -> int:
    # dp[c] = paths to reach (current_row, c)
    dp = [1] * n   # first row: only 1 way (go right)
    for _ in range(1, m):
        for c in range(1, n):
            dp[c] += dp[c-1]   # paths from above + paths from left
    return dp[-1]
Dry Run
m=3, n=3

dp = [1, 1, 1]  (first row: only 1 way each, going right)

Row 1: c=1: dp[1]+=dp[0] → dp=[1,2,1]? No: dp[1]=dp[1]+dp[0]=1+1=2
             dp[2]=dp[2]+dp[1]=1+2=3 → dp=[1,2,3]

Intuition

To reach any cell (i, j) you can only arrive from the cell directly above (i-1, j) or directly to the left (i, j-1). So dp[i][j] = dp[i-1][j] + dp[i][j-1]. The top row and left column are all 1 (only one way to reach them — keep moving right or down). Fill the grid left-to-right, top-to-bottom, and the answer is dp[m-1][n-1].

Complexity Analysis

Time: O(m × n). Space: O(n) — rolling 1D array.

Key Takeaway

Unique Paths is solvable in O(1) space and O(1) time with the combinatorics formula C(m+n-2, m-1), but the DP grid makes the reasoning transparent and extends naturally to Unique Paths II (obstacles). Always mention the closed-form if asked about further optimisation.

🟢 How to Identify DP Problems

Ask yourself: (1) Does the problem ask for a count, maximum, minimum, or boolean about all ways to achieve something? (2) If I brute-force it with recursion, am I solving the same subproblem repeatedly? If yes to both, it is almost certainly DP. Common keywords: "number of ways," "minimum cost," "maximum profit," "can you reach," "longest/shortest."

How to Communicate Complexity

Interviewers listen carefully to how you express complexity. Here is the script that conveys confidence:

🟢 Complexity Communication Script

Space: "I am using a hash map that can grow to at most n entries in the worst case, so the space complexity is O(n). The output array does not count towards auxiliary space."

Final Problem 1 — Jump Game Intermediate LeetCode ↗
Problem Statement

Given an array nums where nums[i] is the maximum jump length from index i, return True if you can reach the last index starting from index 0.

Example: [2,3,1,1,4] → True. [3,2,1,0,4] → False

Intuition

Greedy. Track the farthest index reachable. If the current index is ever beyond the farthest reach, you are stuck.

Implementation
Python 
def can_jump(nums: list[int]) -> bool:
    reach = 0   # farthest index we can reach
    for i, jump in enumerate(nums):
        if i > reach:
            return False   # stranded — cannot reach this index
        reach = max(reach, i + jump)
    return True

Jump Game is a greedy problem: maintain the furthest reachable index and extend it greedily. If your loop index ever exceeds reach, you are stuck — return False. No backtracking is needed; a longer reach strictly dominates a shorter one.

Final Problem 2 — Lowest Common Ancestor (Binary Tree) Intermediate LeetCode ↗
Problem Statement

Given the root of a binary tree (not a BST) and two nodes p and q, find their lowest common ancestor.

Intuition

Post-order DFS. Return the node if it matches p or q. The LCA is the first node where both left and right subtrees return non-None.

Implementation
Python 
from typing import Optional

def lca_binary_tree(root: Optional[TreeNode],
                    p: TreeNode, q: TreeNode) -> Optional[TreeNode]:
    if not root or root == p or root == q:
        return root   # found one of the targets (or end of branch)

    left  = lca_binary_tree(root.left,  p, q)
    right = lca_binary_tree(root.right, p, q)

    if left and right:
        return root    # p and q split here → this node is the LCA
    return left if left else right  # both in same subtree

      5   1
     / \ / \

      / \
     7   4

  3≠p, 3≠q
  left  = lca(5,p=5,q=1): root==p → return 5
  right = lca(1,p=5,q=1): root==q → return 1
  left AND right both non-None → return root=3

Time: O(n). Space: O(h).

Key Takeaway

LCA in a plain binary tree (not BST) relies on the post-order observation: the first node where p appears in one subtree and q in the other (or the node itself is p or q) is the LCA. Pure recursive, no parent pointers or BFS required.

Final Problem 3 — Non-Overlapping Intervals Intermediate LeetCode ↗
Problem Statement

Given an array of intervals, find the minimum number of intervals you must remove to make the rest non-overlapping.

Example: [[1,2],[2,3],[3,4],[1,3]] → 1 (remove [1,3])

Intuition

Greedy. Sort by end time. Greedily keep intervals with the earliest end time. If an interval overlaps the last kept one, discard it.

Implementation
Python 
def erase_overlap_intervals(intervals: list[list[int]]) -> int:
    if not intervals: return 0
    intervals.sort(key=lambda x: x[1])  # sort by end time

    removed = 0
    last_end = intervals[0][1]   # end of last kept interval

    for start, end in intervals[1:]:
        if start < last_end:        # overlap: discard this interval
            removed += 1
        else:                       # no overlap: keep it
            last_end = end
    return removed

Key Takeaway

Non-Overlapping Intervals reduces to the Activity Selection problem: sort by end time, greedily keep each interval that does not overlap the last kept one, and remove the rest. Answer = n minus intervals kept.

Final Problem 4 — Number of Islands (DFS) Intermediate LeetCode ↗
Problem Statement

Same as Problem 7.1 — but this time solve it using DFS instead of BFS.

Intuition

Graph DFS. Flood-fill each island by marking cells visited.

Implementation
Python — DFS version 
def num_islands_dfs(grid: list[list[str]]) -> int:
    if not grid: return 0
    rows, cols = len(grid), len(grid[0])

    def dfs(r, c):
        if not (0 <= r < rows and 0 <= c < cols) or grid[r][c] != '1':
            return
        grid[r][c] = '0'   # mark visited
        dfs(r+1,c); dfs(r-1,c); dfs(r,c+1); dfs(r,c-1)

    count = 0
    for r in range(rows):
        for c in range(cols):
            if grid[r][c] == '1':
                dfs(r, c)
                count += 1
    return count

Final Problem 5 — Trapping Rain Water Advanced LeetCode ↗
Problem Statement

Given an array height where each element represents the height of a bar, compute how much water is trapped between bars after rain.

Example: [0,1,0,2,1,0,1,3,2,1,2,1] → 6

Intuition

Water above position i = min(max height to its left, max height to its right) − height[i]. Use two pointers: left and right, tracking the maximum height seen from each side. Process from whichever side has the smaller maximum.

Implementation
Python 
def trap(height: list[int]) -> int:
    left, right = 0, len(height) - 1
    max_left = max_right = water = 0

    while left < right:
        if height[left] <= height[right]:
            if height[left] >= max_left:
                max_left = height[left]
            else:
                water += max_left - height[left]   # water fills here
            left += 1
        else:
            if height[right] >= max_right:
                max_right = height[right]
            else:
                water += max_right - height[right]
            right -= 1

    return water

Final Problem 6 — Longest Palindromic Substring Intermediate LeetCode ↗
Problem Statement

Given a string s, return the longest palindromic substring.

Example: "babad" → "bab" or "aba"

Intuition

Expand Around Centre. For each character (and each pair of adjacent characters), try expanding outward as long as the characters match. Track the longest expansion seen.

Implementation
Python 
def longest_palindrome(s: str) -> str:
    best_start = best_len = 0

    def expand(lo: int, hi: int):
        nonlocal best_start, best_len
        while lo >= 0 and hi < len(s) and s[lo] == s[hi]:
            lo -= 1; hi += 1
        length = hi - lo - 1
        if length > best_len:
            best_len   = length
            best_start = lo + 1

    for i in range(len(s)):
        expand(i, i)      # odd-length palindromes
        expand(i, i + 1) # even-length palindromes

    return s[best_start: best_start + best_len]
