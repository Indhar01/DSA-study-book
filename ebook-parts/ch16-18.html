The Problem-Solving Framework

Technical knowledge is necessary but not sufficient. A candidate who knows every data structure but freezes under pressure, or who jumps straight to code without thinking, will still fail. This chapter gives you a repeatable framework for any technical interview — from understanding the problem to delivering a clean, communicated solution.

The UMPIRE Method

UMPIRE is a six-step framework that guides you from a blank problem statement to a working, optimised solution while keeping the interviewer engaged at every step.

LetterStepWhat You Do
UUnderstandRestate the problem in your own words. Ask clarifying questions. Identify input/output types, constraints, edge cases.
MMatchWhich pattern does this look like? Array? Tree? Graph? DP? Look for known templates.
PPlanExplain your approach before writing a single line of code. Walk through an example. State the expected complexity.
IImplementCode cleanly. Use meaningful variable names. Add short inline comments at decision points.
RReviewTrace through your code manually with a small example. Verify it handles edge cases.
EEvaluateState the time and space complexity aloud. Discuss trade-offs. Offer to optimise if time allows.

UMPIRE Worked Example: Two Sum

Let us walk through UMPIRE on a simple problem to internalise the method.

📘 U — Understand

"So, given an array of integers and a target, I need to return the two indices that add up to the target. There is exactly one valid answer, and I should not use the same element twice. Can the array contain negative numbers? Can it be empty?" (Interviewer answers yes and no.) "OK, and the return type is a list of two integers."

📘 M — Match

"This feels like a hash map problem. For each element, I need to quickly find if its complement exists. A hash map gives me O(1) lookup, which is exactly what I need."

📘 P — Plan

"I will iterate through the array. For each element x, I compute complement = target - x. If the complement is in my map, I return both indices. Otherwise, I store x → index in the map. This runs in O(n) time and O(n) space."

📘 I — Implement

Code the solution as shown in Chapter 4, Problem 4.1.

📘 R — Review

"Let me trace through [2,7,11,15] with target 9. i=0: x=2, complement=7, not in map, store {2:0}. i=1: x=7, complement=2, 2 IS in map at index 0. Return [0,1]. ✓"

📘 E — Evaluate

"Time complexity is O(n) — one pass, each lookup is O(1). Space complexity is O(n) — the map can hold at most n entries. Could we do it in O(1) space? Only if the array were sorted — then two pointers would work. But the problem doesn't guarantee sorted order."

How to Communicate Complexity

Interviewers listen carefully to how you express complexity. Here is the script that conveys confidence:

🟢 Complexity Communication Script

Time: "The outer loop runs n times. Inside, each operation is O(1) amortised — hash map lookup and insert. So the total time complexity is O(n)."

Space: "I am using a hash map that can grow to at most n entries in the worst case, so the space complexity is O(n). The output array does not count towards auxiliary space."

Trade-off: "If I needed O(1) space, I could sort the array first in O(n log n) and then use two pointers in O(n), but that changes the time complexity."

Common Interview Mistakes and How to Fix Them

MistakeWhat the Interviewer ThinksHow to Fix It
Jumping straight to code without planning "Does not think before acting. Will write buggy code." Always explain your approach and trace a small example before typing.
Staying silent while thinking "Is stuck. Has no strategy." Think out loud: "OK, first thought is brute force O(n²)… but if I use a hash map…"
Not handling edge cases "Inexperienced. Ships buggy code." After your core solution, always ask: "What if the input is empty? What if n=1?"
Using bad variable names (i, j, x, y everywhere) "Writes unreadable code." Use meaningful names: left, right, slow, fast, current_sum, min_price.
Forgetting to state complexity "Does not think about performance." At the end of every solution, say: "Time is O(…), space is O(…)"
Getting stuck and going silent "Cannot handle pressure." Say "I am thinking through a brute-force approach first to ground myself" or ask: "Can I get a small hint on the intended data structure?"

Pattern Recognition Guide

The best interviewers are not looking for memorised solutions — they are looking for pattern recognition. This chapter maps common problem signals to the data structures and algorithms that solve them. Internalise these mappings and you will spend less time searching for a starting point and more time building the solution.

The Pattern Decision Framework

When you read a problem, ask these questions in order:

ASCII — Pattern Decision Tree 
Is the input sorted (or does sorting help)?
  └─ Yes → Binary Search or Two Pointers

Is the problem about a contiguous subarray/substring?
  └─ Yes → Sliding Window

Does it ask "have I seen X before" or "count occurrences"?
  └─ Yes → Hash Map / Hash Set

Is the data hierarchical with parent-child relationships?
  └─ Yes → Tree (DFS or BFS)
       └─ Sorted values needed? → BST
       └─ Level-by-level processing? → BFS Queue

Is the data a network of connections?
  └─ Yes → Graph (DFS/BFS/Union-Find)

Does it ask for "all combinations/permutations/subsets"?
  └─ Yes → Backtracking

Does it ask for min/max of something with overlapping subproblems?
  └─ Yes → Dynamic Programming

Does it ask for the "smallest k" or "largest k" or a running median?
  └─ Yes → Heap (Priority Queue)

Does it involve matching, nesting, or "next greater element"?
  └─ Yes → Stack (monotonic stack for NGE)

Final Problem 1 — Jump Game Intermediate
Problem Statement

Given an array nums where nums[i] is the maximum jump length from index i, return True if you can reach the last index starting from index 0.

Example: [2,3,1,1,4] → True. [3,2,1,0,4] → False

Pattern

Greedy. Track the farthest index reachable. If the current index is ever beyond the farthest reach, you are stuck.

Implementation
Python 
def can_jump(nums: list[int]) -> bool:
    reach = 0   # farthest index we can reach
    for i, jump in enumerate(nums):
        if i > reach:
            return False   # stranded — cannot reach this index
        reach = max(reach, i + jump)
    return True
Complexity Analysis

Time: O(n). Space: O(1).

Final Problem 2 — Lowest Common Ancestor (Binary Tree) Intermediate
Problem Statement

Given the root of a binary tree (not a BST) and two nodes p and q, find their lowest common ancestor.

Pattern

Post-order DFS. Return the node if it matches p or q. The LCA is the first node where both left and right subtrees return non-None.

Implementation
Python 
from typing import Optional

def lca_binary_tree(root: Optional[TreeNode],
                    p: TreeNode, q: TreeNode) -> Optional[TreeNode]:
    if not root or root == p or root == q:
        return root   # found one of the targets (or end of branch)

    left  = lca_binary_tree(root.left,  p, q)
    right = lca_binary_tree(root.right, p, q)

    if left and right:
        return root    # p and q split here → this node is the LCA
    return left if left else right  # both in same subtree
Complexity Analysis

Time: O(n). Space: O(h).

Final Problem 3 — Non-Overlapping Intervals Intermediate
Problem Statement

Given an array of intervals, find the minimum number of intervals you must remove to make the rest non-overlapping.

Example: [[1,2],[2,3],[3,4],[1,3]] → 1 (remove [1,3])

Pattern

Greedy. Sort by end time. Greedily keep intervals with the earliest end time. If an interval overlaps the last kept one, discard it.

Implementation
Python 
def erase_overlap_intervals(intervals: list[list[int]]) -> int:
    if not intervals: return 0
    intervals.sort(key=lambda x: x[1])  # sort by end time

    removed = 0
    last_end = intervals[0][1]   # end of last kept interval

    for start, end in intervals[1:]:
        if start < last_end:        # overlap: discard this interval
            removed += 1
        else:                       # no overlap: keep it
            last_end = end
    return removed
Complexity Analysis

Time: O(n log n) — dominated by sort. Space: O(1).

Final Problem 4 — Number of Islands (DFS) Intermediate
Problem Statement

Same as Problem 7.1 — but this time solve it using DFS instead of BFS.

Pattern

Graph DFS. Flood-fill each island by marking cells visited.

Implementation
Python — DFS version 
def num_islands_dfs(grid: list[list[str]]) -> int:
    if not grid: return 0
    rows, cols = len(grid), len(grid[0])

    def dfs(r, c):
        if not (0 <= r < rows and 0 <= c < cols) or grid[r][c] != '1':
            return
        grid[r][c] = '0'   # mark visited
        dfs(r+1,c); dfs(r-1,c); dfs(r,c+1); dfs(r,c-1)

    count = 0
    for r in range(rows):
        for c in range(cols):
            if grid[r][c] == '1':
                dfs(r, c)
                count += 1
    return count
Complexity Analysis

Time: O(m × n). Space: O(m × n) — worst case recursion depth for one large island.

Final Problem 5 — Trapping Rain Water Advanced
Problem Statement

Given an array height where each element represents the height of a bar, compute how much water is trapped between bars after rain.

Example: [0,1,0,2,1,0,1,3,2,1,2,1] → 6

Intuition

Water above position i = min(max height to its left, max height to its right) − height[i]. Use two pointers: left and right, tracking the maximum height seen from each side. Process from whichever side has the smaller maximum.

Implementation
Python 
def trap(height: list[int]) -> int:
    left, right = 0, len(height) - 1
    max_left = max_right = water = 0

    while left < right:
        if height[left] <= height[right]:
            if height[left] >= max_left:
                max_left = height[left]
            else:
                water += max_left - height[left]   # water fills here
            left += 1
        else:
            if height[right] >= max_right:
                max_right = height[right]
            else:
                water += max_right - height[right]
            right -= 1

    return water
Complexity Analysis

Time: O(n) — one pass. Space: O(1).

Key Takeaway

Two-pointer from both ends with running max values eliminates the need for prefix/suffix max arrays. The invariant: whichever side has the smaller maximum bottlenecks the water level — process that side first.

Final Problem 6 — Longest Palindromic Substring Intermediate
Problem Statement

Given a string s, return the longest palindromic substring.

Example: "babad" → "bab" or "aba"

Intuition

Expand Around Centre. For each character (and each pair of adjacent characters), try expanding outward as long as the characters match. Track the longest expansion seen.

Implementation
Python 
def longest_palindrome(s: str) -> str:
    best_start = best_len = 0

    def expand(lo: int, hi: int):
        nonlocal best_start, best_len
        while lo >= 0 and hi < len(s) and s[lo] == s[hi]:
            lo -= 1; hi += 1
        length = hi - lo - 1
        if length > best_len:
            best_len   = length
            best_start = lo + 1

    for i in range(len(s)):
        expand(i, i)      # odd-length palindromes
        expand(i, i + 1) # even-length palindromes

    return s[best_start: best_start + best_len]
Complexity Analysis

Time: O(n²) — 2n centres, each expand up to O(n). Space: O(1).
