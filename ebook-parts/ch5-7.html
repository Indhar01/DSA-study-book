Linked Lists

Arrays store elements in contiguous memory slots, like seats in a row. Linked lists take a completely different approach — each element lives wherever it fits in memory, but carries a note pointing to the next element. Understanding this difference unlocks a new class of problems.

The Treasure Hunt Analogy

🟣 Analogy

Imagine a treasure hunt where the first clue is at the starting location. When you open it, it tells you where to find the second clue. The second clue tells you the location of the third, and so on. Each clue only knows about the next clue — not all of them at once. That is a linked list. The starting location is the head. Each clue is a node. The final clue says "you've reached the end" — that is None.

Singly Linked List Implementation

Python — Node and LinkedList 
class ListNode:
    def __init__(self, val: int = 0, next=None):
        self.val  = val   # the data stored in this node
        self.next = next  # pointer to the next node (or None)

# Helper to build a linked list from a Python list
def build_list(values: list[int]) -> ListNode:
    dummy = ListNode(0)
    cur = dummy
    for v in values:
        cur.next = ListNode(v)
        cur = cur.next
    return dummy.next

# Helper to convert a linked list back to a Python list (for testing)
def list_to_array(head: ListNode) -> list[int]:
    result = []
    while head:
        result.append(head.val)
        head = head.next
    return result

Why Not Just Use Arrays?

Linked lists shine where arrays struggle:

  • O(1) insert/delete at the head (or any known position) — no shifting required.
  • Dynamic sizing — no pre-allocation needed.

Their weaknesses: no random access (you must traverse from the head), and extra memory for the pointer in each node.

The Fast and Slow Pointer (Runner) Technique

This clever technique uses two pointers that move through the list at different speeds — the "slow" pointer moves one step at a time, the "fast" pointer moves two. It solves cycle detection, finding the middle element, and more — all in O(n) with O(1) space.

🟣 Analogy — Floyd's Tortoise and Hare

Imagine a circular racetrack. A tortoise moves at 1 step per second. A hare moves at 2. If the track is a loop, the hare will eventually lap the tortoise and they will meet. If there is no loop, the hare will reach the end (None) without ever catching the tortoise. This is the intuition behind Floyd's cycle detection algorithm.

Problem 5.1 — Reverse a Linked List Beginner
Problem Statement

Given the head of a singly linked list, reverse the list and return the new head.

Example: 1→2→3→4→5 → 5→4→3→2→1

Intuition

Walk through the list one node at a time. For each node, flip its next pointer to point backward instead of forward. We need three pointers: prev (what came before), curr (where we are), and nxt (what comes next — saved before we overwrite).

Implementation
Python 
def reverse_list(head: ListNode) -> ListNode:
    prev = None
    curr = head
    while curr:
        nxt        = curr.next  # save next before overwriting
        curr.next  = prev       # reverse the pointer
        prev       = curr       # advance prev
        curr       = nxt        # advance curr
    return prev  # prev is the new head
Dry Run
List: 1→2→3→None

Start: prev=None, curr=1

Step 1: nxt=2, curr.next=None, prev=1, curr=2
  None←1  2→3→None

Step 2: nxt=3, curr.next=1, prev=2, curr=3
  None←1←2  3→None

Step 3: nxt=None, curr.next=2, prev=3, curr=None
  None←1←2←3

Return prev = 3 (new head) ✓
Complexity Analysis

Time: O(n) — One pass through all n nodes. Space: O(1) — Three pointer variables.

Key Takeaway

Linked list problems are pointer manipulation problems. Draw the state of the pointers before and after each step. The "save next before overwriting" pattern is fundamental to in-place list operations.

Problem 5.2 — Merge Two Sorted Lists Beginner
Problem Statement

Merge two sorted linked lists and return the merged list (also sorted).

Example: 1→2→4 and 1→3→4 → 1→1→2→3→4→4

Intuition

Use a dummy head node to simplify edge cases. Maintain a pointer to the tail of the merged list. At each step, compare the heads of both lists, attach the smaller one to the tail, and advance that list's pointer. When one list runs out, attach the rest of the other.

Implementation
Python 
def merge_two_lists(l1: ListNode, l2: ListNode) -> ListNode:
    dummy = ListNode(0)   # sentinel node to avoid special-casing the head
    tail  = dummy

    while l1 and l2:
        if l1.val <= l2.val:
            tail.next = l1
            l1 = l1.next
        else:
            tail.next = l2
            l2 = l2.next
        tail = tail.next   # advance the tail

    tail.next = l1 if l1 else l2  # attach whichever list remains
    return dummy.next               # skip the dummy, return real head
Complexity Analysis

Time: O(n + m) where n and m are the lengths of the two lists. Space: O(1) — no new nodes created, just re-wiring existing ones.

Key Takeaway

The dummy head pattern is a recurring technique. It eliminates the need to handle the "empty output" edge case separately, because the dummy is always there as the initial node.

Problem 5.3 — Linked List Cycle Detection Intermediate
Problem Statement

Given the head of a linked list, return True if there is a cycle in the list.

Intuition

Use Floyd's fast-and-slow pointer algorithm. If there is a cycle, the fast pointer will eventually "lap" the slow pointer and they will meet at the same node. If there is no cycle, the fast pointer will reach None.

Implementation
Python 
def has_cycle(head: ListNode) -> bool:
    slow = head
    fast = head
    while fast and fast.next:
        slow = slow.next        # tortoise: 1 step
        fast = fast.next.next   # hare: 2 steps
        if slow == fast:        # they met → cycle exists
            return True
    return False  # fast hit None → no cycle
Complexity Analysis

Time: O(n) — At most n iterations. Space: O(1) — Only two pointers.

Problem 5.4 — Remove Nth Node From End Intermediate
Problem Statement

Given the head of a linked list, remove the nth node from the end and return the head. Do it in one pass.

Example: List = 1→2→3→4→5, n=2 → 1→2→3→5

Intuition

Use two pointers with a gap of n between them. Advance both pointers together until the fast pointer reaches the end. At that point, the slow pointer is exactly at the node before the one to remove. This is a brilliant one-pass trick using the fixed-gap idea.

Implementation
Python 
def remove_nth_from_end(head: ListNode, n: int) -> ListNode:
    dummy = ListNode(0, head)
    fast = dummy
    slow = dummy

    # Advance fast n+1 steps to create a gap of n
    for _ in range(n + 1):
        fast = fast.next

    # Move both until fast reaches the end
    while fast:
        fast = fast.next
        slow = slow.next

    # slow.next is the node to remove
    slow.next = slow.next.next
    return dummy.next
Complexity Analysis

Time: O(n) — One pass. Space: O(1).

Key Takeaway

A fixed gap between two pointers is a powerful one-pass technique. Think: "if the fast pointer is n steps ahead, when it reaches the end, where is the slow pointer?"

Problem 5.5 — Reorder List Intermediate
Problem Statement

Given list L0→L1→...→Ln-1→Ln, reorder it to L0→Ln→L1→Ln-1→L2→Ln-2→... in-place.

Example: 1→2→3→4 → 1→4→2→3

Intuition

This combines three sub-problems: (1) find the middle using fast/slow pointers, (2) reverse the second half, (3) merge the two halves by interleaving.

Implementation
Python 
def reorder_list(head: ListNode) -> None:
    if not head: return

    # Step 1: find the middle
    slow, fast = head, head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next

    # Step 2: reverse second half
    prev, curr = None, slow.next
    slow.next = None  # cut the list in half
    while curr:
        nxt = curr.next; curr.next = prev; prev = curr; curr = nxt

    # Step 3: merge first and reversed second half
    first, second = head, prev
    while second:
        tmp1, tmp2    = first.next, second.next
        first.next    = second
        second.next   = tmp1
        first, second = tmp1, tmp2
Complexity Analysis

Time: O(n) — Three O(n) passes. Space: O(1) — All in-place.

Key Takeaway

Complex linked list problems often decompose into simpler sub-operations (find-middle, reverse, merge) that you already know. Learn those building blocks and combine them.

🔴 Common Beginner Mistake

Forgetting to save curr.next before overwriting curr.next is the most common linked list bug. Always save the next pointer in a temporary variable before any assignment that changes it. Draw the pointers on paper if you are getting confused.

Chapter Summary

  • A linked list is a chain of nodes, each storing a value and a pointer to the next node.
  • O(1) head insert/delete; O(n) access by position.
  • The dummy head pattern simplifies edge cases by providing a stable starting node.
  • Fast/slow pointers detect cycles, find midpoints, and maintain fixed gaps in O(n) time and O(1) space.
  • Complex operations often decompose into: find middle → reverse a half → merge.

Stacks

The stack is one of the simplest and most useful data structures in computer science. Its beauty lies in its constraint: you can only ever interact with the top element. This restriction, far from being a limitation, turns out to be exactly the right model for a surprising number of real-world problems.

The Plate Stack Analogy

🟣 Analogy

Imagine a stack of plates in a cafeteria. You can only place a new plate on top, and you can only pick up the plate on top. You cannot grab a plate from the middle without moving everything above it. This "last in, first out" (LIFO) behaviour is the defining property of a stack. The most recently added item is always the first to be removed.

In Python, we use a regular list as a stack: append() pushes onto the top, and pop() removes from the top. Both operations are O(1) amortised.

Python — Stack Basics 
stack = []
stack.append(1)   # push 1 → [1]
stack.append(2)   # push 2 → [1, 2]
stack.append(3)   # push 3 → [1, 2, 3]
top = stack[-1]   # peek at top: 3 (no removal)
val = stack.pop()  # pop: returns 3, stack → [1, 2]

The Monotonic Stack Pattern

A monotonic stack is a stack that maintains its elements in sorted order (either always increasing or always decreasing from bottom to top). As you process elements, you pop items from the stack that would violate the monotonic property before pushing the new element. This pattern solves "next greater element" and "previous smaller element" problems in O(n) — far better than the naive O(n²) approach.

Problem 6.1 — Valid Parentheses Beginner
Problem Statement

Given a string containing only (, ), {, }, [, ], determine if the input is valid. Open brackets must be closed by the same type of bracket, in the correct order.

Example: "()[]{}" → True; "(]" → False

Intuition

Use a stack. Push every opening bracket. When you encounter a closing bracket, check if the top of the stack is its matching opening bracket. If it is, pop and continue. If not, the string is invalid. At the end, the stack must be empty.

Implementation
Python 
def is_valid(s: str) -> bool:
    stack = []
    mapping = {')': '(', '}': '{', ']': '['}
    for char in s:
        if char in mapping:          # it's a closing bracket
            top = stack.pop() if stack else '#'
            if mapping[char] != top:  # mismatch
                return False
        else:
            stack.append(char)        # opening bracket: push it
    return not stack               # valid only if nothing unmatched remains
Complexity Analysis

Time: O(n). Space: O(n) — worst case stack holds all opening brackets.

Key Takeaway

Whenever a problem involves "matching" or "nesting" (brackets, HTML tags, function calls), think of a stack. The LIFO property naturally handles the innermost-first nesting.

Problem 6.2 — Min Stack Intermediate
Problem Statement

Design a stack that supports push, pop, top, and retrieving the minimum element in O(1) time.

Intuition

Use two stacks: one for the actual values, and one that tracks the current minimum at each level. When we push a new value, we also push the new minimum (the smaller of the new value and the current top of the min stack). When we pop, we pop from both stacks simultaneously.

Implementation
Python 
class MinStack:
    def __init__(self):
        self.stack     = []   # regular stack
        self.min_stack = []   # tracks min at each level

    def push(self, val: int) -> None:
        self.stack.append(val)
        cur_min = min(val, self.min_stack[-1] if self.min_stack else val)
        self.min_stack.append(cur_min)

    def pop(self) -> None:
        self.stack.pop()
        self.min_stack.pop()

    def top(self) -> int:
        return self.stack[-1]

    def get_min(self) -> int:
        return self.min_stack[-1]
Complexity Analysis

All operations: O(1). Space: O(n) — two stacks, each up to n elements.

Problem 6.3 — Daily Temperatures Intermediate
Problem Statement

Given a list of daily temperatures, for each day, find how many days until a warmer temperature. If no warmer day exists, use 0.

Example: [73,74,75,71,69,72,76,73] → [1,1,4,2,1,1,0,0]

Intuition

Use a monotonic stack of indices. Push indices onto the stack. Whenever the current temperature is warmer than the temperature at the index on the stack's top, that top index has found its answer. Pop it and record the difference in indices.

Implementation
Python 
def daily_temperatures(temps: list[int]) -> list[int]:
    result = [0] * len(temps)
    stack  = []  # monotonic decreasing stack of indices

    for i, temp in enumerate(temps):
        # While current temp is greater than temp at stack top:
        while stack and temp > temps[stack[-1]]:
            idx = stack.pop()
            result[idx] = i - idx  # days until warmer
        stack.append(i)

    return result
Complexity Analysis

Time: O(n) — Each index is pushed and popped at most once. Space: O(n).

Key Takeaway

The monotonic stack answers "next greater element" queries in O(n). Store indices (not values) on the stack so you can compute distances.

Problem 6.4 — Largest Rectangle in Histogram Advanced
Problem Statement

Given an array of heights representing a histogram, find the area of the largest rectangle that fits under it.

Example: [2,1,5,6,2,3] → 10

Intuition

For each bar, the largest rectangle using that bar as its limiting height extends left and right as far as possible without hitting a shorter bar. We use a monotonic increasing stack: when we encounter a bar shorter than the top of the stack, the top bar can no longer extend right. Pop it and compute its maximum area using the remaining stack top to determine its left boundary.

Implementation
Python 
def largest_rectangle(heights: list[int]) -> int:
    stack  = []   # monotonic increasing stack of (index, height)
    best   = 0
    heights.append(0)  # sentinel: force all bars to be popped at the end

    for i, h in enumerate(heights):
        start = i
        while stack and stack[-1][1] > h:
            idx, height = stack.pop()
            best  = max(best, height * (i - idx))
            start = idx   # can extend left to where the popped bar started
        stack.append((start, h))

    heights.pop()   # restore original array
    return best
Complexity Analysis

Time: O(n) — Each bar is pushed and popped once. Space: O(n).

Key Takeaway

The sentinel (appending 0) is a clean trick to force all remaining stack elements to be processed at the end of the loop without extra post-loop code.

Chapter Summary

  • A stack is LIFO — last in, first out. In Python, use a list with append() and pop().
  • Use stacks for matching/nesting problems (parentheses, HTML tags).
  • The monotonic stack answers "next greater/smaller element" queries in O(n).
  • The dual-stack pattern (Min Stack) lets you augment a stack with constant-time additional queries.
  • A sentinel value can simplify the handling of edge cases at array boundaries.

Queues and Deques

If a stack is a pile of plates, a queue is a line of people waiting at a ticket counter. The first person to arrive is the first to be served. This simple principle — first in, first out — is the backbone of level-order traversal, shortest path algorithms, and more.

Queue: First In, First Out (FIFO)

🟣 Analogy

Imagine people lining up to buy concert tickets. The first person who arrived waits at the front. New arrivals join at the back. When a ticket window opens, the person at the front is served. No cutting in line! This is FIFO. In computing, queues are used for task scheduling, print spoolers, BFS graph traversal, and any scenario where fairness of processing order matters.

Python — Queue Using collections.deque 
from collections import deque

queue = deque()
queue.append(1)       # enqueue: add to right end
queue.append(2)       # [1, 2]
queue.append(3)       # [1, 2, 3]
front = queue[0]     # peek front: 1
val   = queue.popleft() # dequeue: remove from left end → 1, queue=[2,3]
📘 Why Not Use a Regular List for Queues?

Python's list.pop(0) removes the first element but has to shift every remaining element one position to the left — that is O(n). A collections.deque uses a doubly-linked internal structure so popleft() is O(1). Always use deque for queues.

Deque: Double-Ended Queue

A deque (pronounced "deck") allows O(1) add and remove from both ends. This makes it a generalisation of both stacks and queues, and it is particularly powerful for the "sliding window maximum" problem.

Problem 7.1 — Number of Islands (BFS Version) Intermediate
Problem Statement

Given a 2D grid of '1' (land) and '0' (water), count the number of islands. An island is surrounded by water and formed by connecting adjacent land cells horizontally or vertically.

Example: Grid with two clusters of 1s → Output: 2

Intuition

Think of it as a flood-fill. When you discover a land cell, use BFS to "flood" (mark as visited) all connected land cells. Each time you start a new flood from an unvisited land cell, you have found a new island. Count how many floods you initiate.

Implementation
Python 
from collections import deque

def num_islands(grid: list[list[str]]) -> int:
    if not grid: return 0
    rows, cols = len(grid), len(grid[0])
    count = 0

    def bfs(r, c):
        queue = deque([(r, c)])
        grid[r][c] = '0'  # mark visited immediately on enqueue
        while queue:
            row, col = queue.popleft()
            for dr, dc in [(1,0),(-1,0),(0,1),(0,-1)]:
                nr, nc = row + dr, col + dc
                if 0 <= nr < rows and 0 <= nc < cols and grid[nr][nc] == '1':
                    grid[nr][nc] = '0'
                    queue.append((nr, nc))

    for r in range(rows):
        for c in range(cols):
            if grid[r][c] == '1':
                bfs(r, c)
                count += 1
    return count
Complexity Analysis

Time: O(m × n) — Each cell is visited at most once. Space: O(min(m, n)) — Queue size is bounded by the perimeter of the BFS frontier.

Key Takeaway

BFS uses a queue. It explores all neighbours at distance 1 before distance 2, making it ideal for shortest-path and connected-components problems on grids and graphs.

Problem 7.2 — Sliding Window Maximum Advanced
Problem Statement

Given an array nums and window size k, return a list of the maximum value in each window of size k as it slides across the array.

Example: nums=[1,3,-1,-3,5,3,6,7], k=3 → [3,3,5,5,6,7]

Intuition

Use a monotonic deque that stores indices in decreasing order of their values. When we slide the window: (1) remove indices from the front that are outside the window; (2) remove indices from the back whose values are smaller than the current value (they can never be the maximum while the current element is in the window). The front of the deque always holds the maximum.

Implementation
Python 
from collections import deque

def max_sliding_window(nums: list[int], k: int) -> list[int]:
    dq     = deque()   # stores indices, values are decreasing
    result = []

    for i, num in enumerate(nums):
        # Remove elements outside the window from the front
        while dq and dq[0] < i - k + 1:
            dq.popleft()
        # Remove smaller elements from the back (they'll never be max)
        while dq and nums[dq[-1]] < num:
            dq.pop()
        dq.append(i)
        # The front of deque is the max of the current window
        if i >= k - 1:
            result.append(nums[dq[0]])

    return result
Complexity Analysis

Time: O(n) — Each element is added and removed from the deque at most once. Space: O(k) — The deque holds at most k indices.

Key Takeaway

The deque (double-ended queue) is the perfect tool for sliding window problems that need to efficiently track the maximum or minimum within a window as it moves.

Problem 7.3 — Binary Tree Level Order Traversal Beginner
Problem Statement

Given the root of a binary tree, return the level-order traversal of its nodes' values as a list of lists (one list per level).

Intuition

Use a queue. Start with the root. Process all nodes at level 0, then level 1, etc. The trick for separating levels: at the start of each level, record how many nodes are currently in the queue — that is exactly how many nodes belong to this level.

Implementation
Python 
from collections import deque

def level_order(root) -> list[list[int]]:
    if not root: return []
    result = []
    queue  = deque([root])

    while queue:
        level_size = len(queue)   # nodes in the current level
        level = []
        for _ in range(level_size):
            node = queue.popleft()
            level.append(node.val)
            if node.left:  queue.append(node.left)
            if node.right: queue.append(node.right)
        result.append(level)

    return result
Complexity Analysis

Time: O(n) — Visit each node once. Space: O(n) — Last level can have n/2 nodes in the queue.

Problem 7.4 — First Non-Repeating Character in a Stream Intermediate
Problem Statement

Given a stream of characters, at each step, find the first non-repeating character. Return '#' if none exists.

Example: Stream "aabcde" → at each step: ['a','#','b','b','b','c']

Intuition

Maintain a queue of characters seen in order, and a frequency map. When asked for the first non-repeating character, drain the front of the queue until you find a character with frequency 1.

Implementation
Python 
from collections import deque, defaultdict

def first_non_repeating_stream(stream: str) -> list[str]:
    freq  = defaultdict(int)
    queue = deque()
    result = []

    for ch in stream:
        freq[ch] += 1
        queue.append(ch)
        # Remove repeated characters from the front
        while queue and freq[queue[0]] > 1:
            queue.popleft()
        result.append(queue[0] if queue else '#')

    return result
Complexity Analysis

Time: O(n) overall. Space: O(1) — At most 26 characters in the queue (English alphabet).

Chapter Summary

  • A queue is FIFO — first in, first out. In Python, always use collections.deque, not a list.
  • A deque supports O(1) add/remove at both ends — the foundation of the sliding window maximum pattern.
  • BFS uses a queue. The level-separation trick (snapshot queue size at start of level) is fundamental for level-order tree traversal.
  • Monotonic deques (decreasing) efficiently track window maximums as a window slides.
