Trees and Binary Trees

Arrays and linked lists store data in a line. Trees break that constraint and let data branch in multiple directions — opening up an entirely new class of problems and solutions. Once you understand trees, graphs, heaps, and many other structures become much easier to grasp.

The Family Tree Analogy

🟣 Analogy

Think of a family tree. You start at a single ancestor at the top — the root. Each person can have children. Each child can have their own children. There are no cycles (you cannot be your own ancestor). The people with no children are called leaves. The number of connections between a person and the root is their depth. This is exactly how a tree data structure works.

Tree Vocabulary

  • Root: The single top-most node. Every tree has exactly one root.
  • Parent / Child: If node A points to node B, A is B's parent and B is A's child.
  • Leaf: A node with no children.
  • Height: The longest path from a node down to a leaf.
  • Depth: The distance from the root to a given node.
  • Subtree: Any node and all its descendants form a valid subtree.

Binary Tree: At Most Two Children

A binary tree is a tree where every node has at most two children — conventionally called left and right. This seemingly simple constraint unlocks elegant recursive algorithms.

Python — TreeNode Class 
class TreeNode:
    def __init__(self, val: int = 0,
                 left=None, right=None):
        self.val   = val
        self.left  = left
        self.right = right

# Build a small tree:  1
#                     / \
#                    2   3
root = TreeNode(1,
        TreeNode(2),
        TreeNode(3))

Tree Traversals

Traversal means visiting every node exactly once. There are four canonical ways to traverse a binary tree, each with a different visit order:

TraversalOrderUse Case
InorderLeft → Root → RightPrints BST values in sorted order
PreorderRoot → Left → RightSerialise / copy a tree
PostorderLeft → Right → RootDelete a tree, evaluate expressions
Level OrderLevel by level (BFS)Shortest path, level-based problems
Python — All Four Traversals 
from collections import deque
from typing import Optional, List

# Recursive DFS traversals
def inorder(root: Optional[TreeNode]) -> List[int]:
    if not root: return []
    return inorder(root.left) + [root.val] + inorder(root.right)

def preorder(root: Optional[TreeNode]) -> List[int]:
    if not root: return []
    return [root.val] + preorder(root.left) + preorder(root.right)

def postorder(root: Optional[TreeNode]) -> List[int]:
    if not root: return []
    return postorder(root.left) + postorder(root.right) + [root.val]

# Iterative level-order (BFS)
def level_order_flat(root: Optional[TreeNode]) -> List[int]:
    if not root: return []
    result, q = [], deque([root])
    while q:
        node = q.popleft()
        result.append(node.val)
        if node.left:  q.append(node.left)
        if node.right: q.append(node.right)
    return result
Problem 8.1 — Maximum Depth of Binary Tree Beginner
Problem Statement

Given the root of a binary tree, return its maximum depth — the number of nodes along the longest path from root to the farthest leaf.

Example: Tree [3,9,20,null,null,15,7] → 3

Intuition

The depth of any node is 1 + the maximum depth of its two subtrees. An empty tree has depth 0. This is a perfect recursive definition — the base case and recursive case are both crystal clear.

Implementation
Python 
def max_depth(root: Optional[TreeNode]) -> int:
    if not root:
        return 0   # base case: empty tree has depth 0
    left_depth  = max_depth(root.left)
    right_depth = max_depth(root.right)
    return 1 + max(left_depth, right_depth)
Complexity Analysis

Time: O(n) — Every node is visited once. Space: O(h) where h is the height (O(log n) for balanced, O(n) worst case for skewed).

Key Takeaway

Tree recursion follows a pattern: handle None, recurse left, recurse right, combine results. This template solves the majority of tree problems.

Problem 8.2 — Invert Binary Tree Beginner
Problem Statement

Given the root of a binary tree, invert the tree (mirror it), and return its root.

Intuition

At every node, swap its left and right children. Then recursively do the same for every subtree. The base case is a None node.

Implementation
Python 
def invert_tree(root: Optional[TreeNode]) -> Optional[TreeNode]:
    if not root:
        return None
    root.left, root.right = invert_tree(root.right), invert_tree(root.left)
    return root
Complexity Analysis

Time: O(n). Space: O(h).

Problem 8.3 — Same Tree Beginner

Implementation
Python 
def is_same_tree(p: Optional[TreeNode], q: Optional[TreeNode]) -> bool:
    if not p and not q: return True   # both empty
    if not p or  not q: return False  # one empty, one not

Problem 8.4 — Diameter of Binary Tree Intermediate
Problem Statement

The diameter of a binary tree is the length of the longest path between any two nodes (not necessarily passing through the root). Return the diameter.

Intuition

For each node, the longest path through it = left_height + right_height. Use a DFS that simultaneously computes height (for the parent) and updates a global best diameter.

Implementation
Python 
def diameter_of_binary_tree(root: Optional[TreeNode]) -> int:
    best = [0]  # use a list so inner function can mutate it

    def height(node):
        if not node: return 0
        left  = height(node.left)
        right = height(node.right)
        best[0] = max(best[0], left + right)  # diameter through this node
        return 1 + max(left, right)           # height for parent

    height(root)
    return best[0]
Complexity Analysis

Time: O(n). Space: O(h).

Key Takeaway

Many tree problems require tracking two pieces of information simultaneously: something you return up the recursion stack (height) and something you update as a side effect (best diameter). This dual-return pattern is extremely common.

Problem 8.5 — Binary Tree Maximum Path Sum Advanced
Problem Statement

A path in a binary tree is a sequence of nodes where each pair of adjacent nodes has an edge. The path does not need to pass through the root. Find the maximum sum of any path.

Example: Tree [-10,9,20,null,null,15,7] → 42 (path 15→20→7)

Intuition

Same dual-return pattern as the diameter problem. For each node, the maximum path through it = left_gain + node.val + right_gain (where gain is max(0, subtree_path) — we never include a negative branch). Return only one side (left or right) plus the node value for the parent's calculation.

Implementation
Python 
def max_path_sum(root: Optional[TreeNode]) -> int:
    best = [float('-inf')]

    def gain(node):
        if not node: return 0
        left_gain  = max(gain(node.left),  0)  # ignore negative branches
        right_gain = max(gain(node.right), 0)
        best[0] = max(best[0], node.val + left_gain + right_gain)
        return node.val + max(left_gain, right_gain)  # only one branch upward

    gain(root)
    return best[0]
Complexity Analysis

Time: O(n). Space: O(h).

Chapter Summary

  • A binary tree has at most two children per node: left and right.
  • The four traversals: inorder (L-Root-R), preorder (Root-L-R), postorder (L-R-Root), level-order (BFS).
  • Most tree problems follow: base case (None), recurse left, recurse right, combine.
  • The dual-return pattern tracks two quantities simultaneously: a return value going up, and a global best updated as a side effect.

Binary Search Trees

A binary search tree is a binary tree with a superpower: its structure enforces a sorted ordering across the entire tree. This single constraint — every left descendant is smaller, every right descendant is larger — makes search, insert, and delete all run in O(log n) for balanced trees.

The BST Property

📘 The BST Invariant

For every node X in a BST:
• All nodes in X's left subtree have values strictly less than X's value.
• All nodes in X's right subtree have values strictly greater than X's value.
• This property holds recursively for every subtree.

ASCII — BST Example 
        8
       / \
      3   10
     / \    \
    1   6    14
       / \   /
      4   7 13

Inorder traversal: 1, 3, 4, 6, 7, 8, 10, 13, 14  ← sorted!

Search, Insert, and Delete

Python — BST Search and Insert 
def search_bst(root: Optional[TreeNode], val: int) -> Optional[TreeNode]:
    if not root or root.val == val:
        return root
    if val < root.val:
        return search_bst(root.left,  val)
    return     search_bst(root.right, val)

def insert_bst(root: Optional[TreeNode], val: int) -> TreeNode:
    if not root: return TreeNode(val)  # found insertion spot
    if val < root.val:
        root.left  = insert_bst(root.left,  val)
    else:
        root.right = insert_bst(root.right, val)
    return root
Problem 9.1 — Validate Binary Search Tree Intermediate
Problem Statement

Given the root of a binary tree, determine if it is a valid BST.

Intuition

A common mistake is only checking the immediate parent–child relationship. But a BST must satisfy the property for the entire subtree. The correct approach: pass down a valid range [min_val, max_val] for each node. The root can be anything (−∞, +∞). Going left tightens the upper bound; going right tightens the lower bound.

Implementation
Python 
def is_valid_bst(root: Optional[TreeNode]) -> bool:
    def validate(node, low: float, high: float) -> bool:
        if not node: return True
        if not (low < node.val < high): return False
        return (validate(node.left,  low,      node.val) and
                validate(node.right, node.val, high))

    return validate(root, float('-inf'), float('inf'))
Complexity Analysis

Time: O(n). Space: O(h).

Key Takeaway

When validating a BST, pass min/max bounds down the recursion — do not rely on checking only the direct parent-child relationship.

Problem 9.2 — Lowest Common Ancestor of a BST Intermediate
Problem Statement

Given a BST and two nodes p and q, find their lowest common ancestor (LCA) — the deepest node that has both as descendants.

Intuition

Use the BST property to navigate in one pass. If both p and q are smaller than the current node, go left. If both are larger, go right. The first node where they split (one goes left, one goes right) is the LCA.

Implementation
Python 
def lowest_common_ancestor(root: TreeNode, p: TreeNode, q: TreeNode) -> TreeNode:
    while root:
        if p.val < root.val and q.val < root.val:
            root = root.left       # both smaller → go left
        elif p.val > root.val and q.val > root.val:
            root = root.right      # both larger → go right
        else:
            return root            # split point = LCA
Complexity Analysis

Time: O(h) where h is the height. Space: O(1) — iterative, no stack.

Problem 9.3 — Kth Smallest Element in a BST Intermediate
Problem Statement

Given the root of a BST and an integer k, return the kth smallest element.

Intuition

Inorder traversal of a BST yields values in ascending order. The kth element visited is the answer. Use an iterative inorder traversal for clean control flow.

Implementation
Python 
def kth_smallest(root: Optional[TreeNode], k: int) -> int:
    stack, node = [], root
    while stack or node:
        while node:                 # go as far left as possible
            stack.append(node)
            node = node.left
        node = stack.pop()           # visit this node (inorder)
        k -= 1
        if k == 0: return node.val  # found the kth smallest
        node = node.right            # move to right subtree
Complexity Analysis

Time: O(h + k). Space: O(h) — the explicit stack mirrors the recursion stack.

Chapter Summary

  • A BST satisfies: all left descendants < node.val < all right descendants, recursively.
  • Inorder traversal of a BST always yields values in sorted (ascending) order.
  • When validating a BST, pass min/max bounds down the recursion — never just check parent-child.
  • BST search and LCA run in O(h) — O(log n) for balanced trees, O(n) worst case for skewed.

Heaps and Priority Queues

Imagine a queue where, instead of serving the person who waited longest, you always serve the person with the highest priority. That is exactly what a heap provides — and it makes "find the minimum" or "find the maximum" extremely efficient.

What Is a Heap?

🟣 Analogy

Picture a hospital emergency room. Patients are not seen in the order they arrived — the most critically ill patient is always seen first. When a new critical patient arrives, they jump to the front. When the most critical patient leaves, the next-most-critical takes their place. The structure maintaining this ordering is a heap.

A min-heap always keeps the smallest element at the top. A max-heap keeps the largest. In Python, the built-in heapq module implements a min-heap. To simulate a max-heap, negate all values.

Python — heapq Cheat Sheet 
import heapq

# Min-heap
heap = []
heapq.heappush(heap, 3)   # push
heapq.heappush(heap, 1)
heapq.heappush(heap, 4)
top = heap[0]             # peek minimum: 1 (no removal)
val = heapq.heappop(heap)  # pop minimum: returns 1

# Build heap from list in O(n)
nums = [5, 2, 8, 1]
heapq.heapify(nums)        # in-place, O(n)

# Max-heap: negate values
max_heap = []
heapq.heappush(max_heap, -5)
heapq.heappush(max_heap, -2)
max_val = -heapq.heappop(max_heap)  # returns 5

# k largest elements
k_largest  = heapq.nlargest(3, nums)
k_smallest = heapq.nsmallest(3, nums)
Problem 10.1 — Kth Largest Element in an Array Intermediate
Problem Statement

Given an integer array nums and integer k, return the kth largest element.

Example: [3,2,1,5,6,4], k=2 → 5

Intuition

Maintain a min-heap of size k. As you scan the array, push each element. If the heap grows beyond k, pop the minimum. At the end, the smallest element in the heap is the kth largest overall — it survived by being larger than everything that was ejected.

Implementation
Python 
import heapq

def find_kth_largest(nums: list[int], k: int) -> int:
    heap = []
    for num in nums:
        heapq.heappush(heap, num)
        if len(heap) > k:
            heapq.heappop(heap)   # evict the smallest — it's not top-k
    return heap[0]               # smallest of the top-k = kth largest
Complexity Analysis

Time: O(n log k) — n pushes, each O(log k). Space: O(k) — heap size capped at k.

Key Takeaway

A min-heap of size k is the canonical approach for "top k" problems. It gives you O(n log k) instead of O(n log n) for full sorting.

Problem 10.2 — Merge K Sorted Lists Advanced
Problem Statement

You are given k sorted linked lists. Merge them all into one sorted linked list.

Intuition

Use a min-heap initialised with the first node from each list. Repeatedly pop the minimum node, add it to the result, then push its successor (if any) onto the heap. The heap always contains at most k elements — the "front runners" from each list.

Implementation
Python 
import heapq
from typing import List, Optional

def merge_k_lists(lists: List[Optional[ListNode]]) -> Optional[ListNode]:
    heap = []
    # Seed the heap with the head of each non-empty list
    # Tuple: (node_value, list_index, node) — list_index breaks ties
    for i, node in enumerate(lists):
        if node:
            heapq.heappush(heap, (node.val, i, node))

    dummy = ListNode(0)
    tail  = dummy
    while heap:
        val, i, node = heapq.heappop(heap)
        tail.next = node
        tail = tail.next
        if node.next:
            heapq.heappush(heap, (node.next.val, i, node.next))

    return dummy.next
Complexity Analysis

Time: O(N log k) where N = total nodes, k = number of lists. Space: O(k) — heap holds at most one node per list.

Problem 10.3 — Find Median from Data Stream Advanced
Problem Statement

Design a data structure that accepts a stream of integers and, after each insertion, can return the current median in O(1) time. Insertion should be O(log n).

Intuition

Split the numbers into two halves: a max-heap holding the smaller half, and a min-heap holding the larger half. Keep them balanced (sizes differ by at most 1). The median is the top of the larger half (odd count) or the average of the two tops (even count).

Implementation
Python 
import heapq

class MedianFinder:
    def __init__(self):
        self.lo = []   # max-heap (negate values) — smaller half
        self.hi = []   # min-heap — larger half

    def add_num(self, num: int) -> None:
        heapq.heappush(self.lo, -num)            # always push to lo first
        heapq.heappush(self.hi, -heapq.heappop(self.lo))  # balance: move max(lo) to hi
        if len(self.hi) > len(self.lo):          # keep lo >= hi in size
            heapq.heappush(self.lo, -heapq.heappop(self.hi))

    def find_median(self) -> float:
        if len(self.lo) > len(self.hi):
            return float(-self.lo[0])
        return (-self.lo[0] + self.hi[0]) / 2.0
Complexity Analysis

add_num: O(log n). find_median: O(1). Space: O(n).

Key Takeaway

Two heaps can maintain the lower and upper halves of a dataset, enabling O(1) median queries. This "two-heap" pattern recurs in any problem that needs to track both the largest-of-the-smalls and smallest-of-the-larges.

Chapter Summary

  • A min-heap always pops the smallest element. Python's heapq is a min-heap.
  • Simulate a max-heap by negating values before pushing.
  • A min-heap of size k solves "top k" problems in O(n log k).
  • The two-heap pattern (max-heap of lower half + min-heap of upper half) enables O(1) median queries.

Graphs

Trees are restricted graphs — they have no cycles and a single root. Graphs are the fully general version: nodes connected by edges, with no restrictions on structure. They model road networks, social connections, dependencies, and more. Understanding graphs unlocks a vast category of real-world problems.

Graph Vocabulary

  • Vertex (Node): A single entity in the graph.
  • Edge: A connection between two vertices.
  • Directed / Undirected: In a directed graph, edges have a direction (A→B ≠ B→A). In an undirected graph, edges go both ways.
  • Weighted: Edges can have associated costs or distances.
  • Cycle: A path that starts and ends at the same vertex.
  • Connected Component: A maximal set of vertices where every vertex is reachable from every other.

Graph Representations

Python — Adjacency List (most common) 
from collections import defaultdict

# Build an undirected graph from edge list
def build_graph(n: int, edges: list[list[int]]) -> dict:
    graph = defaultdict(list)
    for u, v in edges:
        graph[u].append(v)
        graph[v].append(u)   # omit this line for directed graphs
    return graph

# Example: 4 nodes, edges 0-1, 0-2, 1-3
# graph = {0:[1,2], 1:[0,3], 2:[0], 3:[1]}

DFS and BFS Templates

Python — DFS (Recursive) 
def dfs(graph: dict, start: int) -> list[int]:
    visited = set()
    order   = []

    def _dfs(node):
        visited.add(node)
        order.append(node)
        for neighbour in graph[node]:
            if neighbour not in visited:
                _dfs(neighbour)

    _dfs(start)
    return order
Python — BFS 
from collections import deque

def bfs(graph: dict, start: int) -> list[int]:
    visited = {start}
    queue   = deque([start])
    order   = []

    while queue:
        node = queue.popleft()
        order.append(node)
        for neighbour in graph[node]:
            if neighbour not in visited:
                visited.add(neighbour)
                queue.append(neighbour)

    return order
Problem 11.1 — Number of Connected Components Intermediate
Problem Statement

Given n nodes labelled 0 to n-1 and a list of undirected edges, count the number of connected components.

Intuition

Use Union-Find (Disjoint Set Union). For each edge, union the two endpoints. Count the number of distinct roots at the end.

Implementation
Python — Union-Find 
def count_components(n: int, edges: list[list[int]]) -> int:
    parent = list(range(n))
    rank   = [0] * n

    def find(x):
        if parent[x] != x:
            parent[x] = find(parent[x])  # path compression
        return parent[x]

    def union(x, y) -> bool:
        rx, ry = find(x), find(y)
        if rx == ry: return False   # already in same component
        if rank[rx] < rank[ry]: rx, ry = ry, rx
        parent[ry] = rx
        if rank[rx] == rank[ry]: rank[rx] += 1
        return True

    components = n
    for u, v in edges:
        if union(u, v):
            components -= 1   # merged two components
    return components
Complexity Analysis

Time: O(n × α(n)) — essentially O(n) with path compression and union-by-rank. α is the inverse Ackermann function, nearly constant. Space: O(n).

Key Takeaway

Union-Find is the go-to structure for dynamic connectivity problems. It answers "are A and B in the same component?" in near-constant time.

Problem 11.2 — Course Schedule (Cycle Detection / Topological Sort) Intermediate
Problem Statement

There are numCourses courses (0 to numCourses-1). Given a list of [a, b] prerequisites (must take b before a), determine if it is possible to finish all courses.

Intuition

This is cycle detection in a directed graph. If there is a cycle in the prerequisite graph, you can never finish all courses (A requires B requires A). Use DFS with three states: unvisited (0), in-progress (1), done (2). If you revisit a node that is in-progress, you have found a cycle.

Implementation
Python 
def can_finish(num_courses: int, prerequisites: list[list[int]]) -> bool:
    graph = defaultdict(list)
    for a, b in prerequisites:
        graph[b].append(a)  # b must be taken before a

    state = [0] * num_courses   # 0=unvisited, 1=in-progress, 2=done

    def has_cycle(node) -> bool:
        if state[node] == 1: return True   # back edge → cycle!
        if state[node] == 2: return False  # already fully explored
        state[node] = 1
        for nb in graph[node]:
            if has_cycle(nb): return True
        state[node] = 2
        return False

    return not any(has_cycle(c) for c in range(num_courses))
Complexity Analysis

Time: O(V + E) — DFS visits every vertex and edge once. Space: O(V + E).

Problem 11.3 — Clone Graph Intermediate
Problem Statement

Given a reference to a node in an undirected connected graph, return a deep copy (clone) of the graph. Each node has a value and a list of neighbours.

Intuition

Use a hash map from original node to clone. DFS the original graph. For each node: if we have already cloned it, return the clone. Otherwise, create a clone, add it to the map, then recursively clone all neighbours and add them to the clone's neighbour list.

Implementation
Python 
class GraphNode:
    def __init__(self, val=0, neighbours=None):
        self.val        = val
        self.neighbours = neighbours if neighbours else []

def clone_graph(node: Optional[GraphNode]) -> Optional[GraphNode]:
    if not node: return None
    cloned = {}   # original node → cloned node

    def dfs(n):
        if n in cloned: return cloned[n]  # already cloned
        copy = GraphNode(n.val)
        cloned[n] = copy
        for nb in n.neighbours:
            copy.neighbours.append(dfs(nb))
        return copy

    return dfs(node)
Complexity Analysis

Time: O(V + E). Space: O(V) — hash map stores all cloned nodes.

Problem 11.4 — Word Ladder (BFS Shortest Path) Advanced
Problem Statement

Given a beginWord, an endWord, and a wordList, find the length of the shortest transformation sequence from begin to end, where each step changes exactly one letter and every intermediate word must be in the word list.

Example: beginWord="hit", endWord="cog", wordList contains valid intermediates → 5 (hit→hot→dot→dog→cog)

Intuition

Model each word as a graph node. Two words are adjacent if they differ by exactly one letter. Finding the shortest path = BFS from beginWord to endWord. To avoid O(n²) edge checking, for each word generate all possible one-letter variants and look them up in the word set.

Implementation
Python 
from collections import deque

def ladder_length(beginWord: str, endWord: str, wordList: list[str]) -> int:
    word_set = set(wordList)
    if endWord not in word_set: return 0

    queue = deque([(beginWord, 1)])  # (word, path_length)
    visited = {beginWord}

    while queue:
        word, length = queue.popleft()
        for i in range(len(word)):
            for c in 'abcdefghijklmnopqrstuvwxyz':
                next_word = word[:i] + c + word[i+1:]
                if next_word == endWord:
                    return length + 1
                if next_word in word_set and next_word not in visited:
                    visited.add(next_word)
                    queue.append((next_word, length + 1))
    return 0  # no path found
Complexity Analysis

Time: O(M × N × 26) where M = word length, N = word list size. Space: O(N).

Key Takeaway

BFS always finds the shortest path in an unweighted graph. When the "graph" is implicit (generated on the fly from word mutations), generate neighbours lazily rather than building the full edge list upfront.

Chapter Summary

  • Represent graphs with an adjacency list (defaultdict(list)) for sparse graphs.
  • DFS explores as deep as possible; great for cycle detection and connected components.
  • BFS explores level by level; always finds the shortest path in unweighted graphs.
  • Union-Find answers connectivity queries in near-constant time with path compression + union-by-rank.
  • Three-color DFS (0/1/2) detects cycles in directed graphs (back edges = cycles).
